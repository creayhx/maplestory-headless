# openstory-console — 冒险岛风格终端控制台

`crates/console` 独立 crate：基于 **ratatui + crossterm** 的全中文终端控制台，
单进程内嵌 bot 库运行（`runtime::run` 跑在 tokio 上，渲染线程独立驱动），
适合在 Windows Terminal 下长时间挂机使用。

**单开与多开是同一个程序、同一份 UI 代码**：`--profiles a.json b.json` 就是多开，
只给一个档案时左栏自动隐藏、版面与此前的单开逐字一致。

与 headless CLI 的关系：**同一套 bot 内核、同一份 config.json、同一份 data 词典**。
CLI 输出英文原文；TUI 在事件层之上做全中文渲染（详见「中文渲染体系」），
底层行为完全一致（`--auto`/`--duration`/`--show-packets` 等参数均可透传）。

---

## 1. 启动

```bash
cargo build --release -p openstory-console
target\release\openstory-console.exe                          # 无参数 → 配置档案选择屏 → 登录向导
target\release\openstory-console.exe --config profiles\xxx.json # 指定档案 → 跳过选择屏
target\release\openstory-console.exe --ip <IP> --port 8484 \
    --account <账号> --password <密码>                    # 参数齐全 → 直接登录(仍先选档案)

# 多开: 一个进程内跑 N 个账号 (无子进程、无 IPC)
target\release\openstory-console.exe --profiles profiles\服A_账号1.json profiles\服A_账号2.json \
    --password <共用密码>
target\release\openstory-console.exe --profiles profiles\a.json profiles\b.json --no-restart

# 管理器模式: 挂上账号但**不登录**, 谁连由你决定 (F4)
target\release\openstory-console.exe --profiles profiles\a.json profiles\b.json --no-autostart
# 只自动启动点名的那些, 其余停在「未启动」
target\release\openstory-console.exe --profiles profiles\a.json profiles\b.json --start <档案名>
```

### 多开模式

`--profiles` 给出 2 个以上档案即进入多开。**与单开是同一个程序、同一份 UI 代码**：
只给一个档案时左栏自动隐藏，版面与此前逐字一致。

| 能力 | 说明 |
|---|---|
| 左栏账号列表 | `● 运行中` / `○ 已结束` / `↻ 等重连`(带倒计时) / `✕ 需人工` / `◌ 未启动` / `◌ 已停止 (手动)`；第二行显示 `Lv/地图/HP` 或阶段 |
| 切换账号 | `Alt+↑↓`（**不是** `Ctrl+↑↓`：Windows Terminal 拿它切自己的标签页，按键到不了程序） |
| 启停 `F4` | 没在跑就**启动**，在跑就**停止**。等价的指令是 `start` / `stop`（对当前选中账号）或 `@all start` / `@<前缀> stop` |
| 看板 `F2` | N 行 × 全字段表格，一眼扫全部账号（阶段列会显示 `Ns后重连` / `需人工` / `已放弃`） |
| 手动重连 `F3` | 清零退避并立刻拉起选中账号（还在跑时只清计数，不把正常工作的号踢下线） |
| 批量下发 | `@all hunt on`（全部）/ `@<档案名前缀> hunt on`（同服一组）。**前缀无命中会报错**，不会退化成发给当前选中账号 |
| 日志/滚动/页签 | **每个账号各自一份**：切号不会把上一个账号的过滤页签与滚动位置带过去 |
| 掉线自动拉起 | 默认开启。`5s → 15s → 45s`，最多 3 次；之后左栏亮红标「已放弃重连 — 需人工」 |
| 关掉自动拉起 | `--no-restart` |
| 密码落盘 | `--remember-password`（默认**不记**）。见下 |

#### 管理器模式 (勾选多个 / `--no-autostart`)

挂上 N 个档案，一个都不登录 —— 这才是"管理多个 bot"的形态。**推荐入口是选择屏**：

```powershell
target\debug\openstory-console.exe          # 不带参数 → 档案选择屏
# Space 勾选多个 → Enter 进入
```

账号列表本来就在那个屏幕上，不必再敲一遍 `--profiles a.json b.json`。等价的
命令行写法（脚本/自动化用）：

```powershell
target\debug\openstory-console.exe --profiles profiles\a.json profiles\b.json --no-autostart
target\debug\openstory-console.exe --profiles profiles\a.json profiles\b.json --start <档案名>
```

| 入口 | 进去之后 |
|---|---|
| 选择屏**单选** + Enter | 老行为：连上这个账号（需要时弹登录向导） |
| 选择屏**勾选多个** + Enter | 全部挂在「未启动」，由你按 `F4` 决定谁连 |
| `--profiles a.json b.json` | 全部**自动登录**（保持向后兼容；脚本用这个） |
| `--profiles … --no-autostart` | 同上但停在「未启动」 |

进入之后：

* 左栏每行显示 `◌ 未启动 — F4 启动`，标题写 `账号 1/2 · 2 个未启动`
* `Alt+↑↓` 选号 → `F4` 启动 → 状态变 `● 连接中…` → 进图后显示 `Lv/地图/HP`
* 再按一次 `F4` 停止 → `◌ 已停止 (手动)`，**不会被自动拉起**
* `@all start` / `@all stop` 批量启停（按档案名前缀也可：`@serverA start`）

**运行中增删账号**（不必重启程序）：

| 指令 | 作用 |
|---|---|
| `profiles` / `profiles list`（别名 `accounts`） | 列出已挂账号与各自状态（`▶` 标当前选中） |
| `profiles add <路径>` | 挂上新账号，停在「未启动」；路径带空格用引号包起来 |
| `profiles remove <档案名>` | 摘掉账号。**只允许摘不在跑的** —— 摘一个正在跑的会话等于把 bot task 变成看不见的孤儿 |

`profiles add` 会真的从文件读出配置当模板：读不出来就拒绝挂上（挂一个永远
启动不了的会话是纯噪音）。命令补全里 `profiles add` 的参数会列出 `profiles/`
目录下的档案。

五条与"自动登录"不同的设计决定：

| 决定 | 为什么 |
|---|---|
| 启动时**不**逐个追问密码 | 那些号现在不登录。启动前排队问 N 个密码正是"一上来就全部登录"的思路 |
| 按 `F4` 时没密码 → **报错**而不是静默 | 静默失败会让用户对着一个没反应的界面反复按键。左栏显示 `✕ 启动失败 — 需人工` |
| `已停止 (手动)` 与掉线重连**严格分开** | 手动停掉的号绝不能被 5 秒后的退避自己唤醒；停掉之后连它结束时报的"连接已关闭"也不许排定拉起 |
| 光标 `▶` 与勾选 `[✓]` 分开 | 光标决定 `N`/`C`/`D` 作用在谁身上，勾选决定 `Enter` 带谁进去。混成一个的话"选了几个号"会随手漂走 |
| 增删账号后 `synced` 视图作废 | 下标全体前移了；不作废的话日志缓存会把 B 的日志当成 A 的继续显示（最难查的一类错） |

**自动拉起的判定规则**（判错会造成重启风暴，所以写清楚）：

| 结束原因 | 是否拉起 |
|---|---|
| 断线 / 连接失败 | ✅ 退避重连（服务器重启的场景） |
| 进程 panic | ✅ 退避重连 |
| 登录失败 / 重连耗尽 | ❌ **绝不**（密码错重试一万次也是同样结果，5 秒一轮会把自己的账号刷成风控）。标记「需人工」 |
| 用户 `quit` / `--duration` 到点 | ❌ 用户自己要停 |
| 本该拉起却没拉成（没加载到档案 / 关掉了自动拉起） | ❌ 但**标记「需人工」**——不能显示成普通"已结束"，那样一个号会无声无息地停掉 |

**密码两种模式**（自动拉起需要明文密码在手：核心层每次重连都要重新登录）：

| 模式 | 开关 | 行为 |
|---|---|---|
| 内存态（**默认**） | 无 / `--no-remember-password` | 密码只在本次进程内，程序重启后需重新输入 |
| 落盘态 | `--remember-password` | 写 `profiles/.manager.json`，让自动拉起跨程序重启生效 |

* 文件是**明文**（不做假加密——解码脚本就在旁边，假加密只会让人误以为安全），
  文件里有一条 `warning` 字段说明这一点；`.gitignore` 已排除
* Unix 权限 `0600`；Windows 依赖用户目录 ACL
* 优先级：**档案里的 `login.password`（你自己写的）> 凭据存储**
* 启动时如果有多开档案缺密码，会列出全部缺密码的档案并逐个询问
  （某一档留空 = 跳过该档，Esc = 全部跳过）。给了 `--password` 或 stdin 不是
  终端时自动跳过询问，不会挡住脚本化启动

### 配置档案选择屏 (profiles/)

无 `--config` / `--profiles` 时启动第一步是**档案选择**：列出 `profiles/*.json`
（每项显示文件名 + 该档的账号/IP 摘要）与根目录旧 config.json（标"(旧)"）。
之后向导预填、`hunt save`、向导回写等一切读写都只落在选中的那份档案。

- ↑↓/jk 选择 · Enter 使用 · Esc 退出程序
- **N** 新建：输入名称（基于 config.default.json 模板；非法字符会拒绝）
- **C** 复制：以选中档案为底复制出新档案（同服多号推荐用法）
- **D** 删除：按两次确认；根 config.json 与 `_` 开头库文件受保护

### 调试统一启动命令（Windows Terminal）

日常调试/观察 TUI 统一用这条命令（Windows Terminal 直启，UTF-8/真彩/鼠标全支持）：

```bash
wt.exe -d <项目目录> cmd /k "target\release\openstory-console.exe --ip <服务器地址> --port 8484"
```

> - 不带 `--account/--password` 会弹登录向导；带全参数则直接进游戏
> - `-d <项目目录>` 指定工作目录（数据词典 `data/*.json` 按工作目录加载）
> - `cmd /k` 让窗口在 TUI 退出后保留，方便看输出
> - 需要自动化场景时追加 `--auto "hunt on"` / `--duration <秒>` 等参数
> - **无头调试**（不占窗口、可抓日志到文件）：
>   `cmd /c "cd /d <项目目录> && target\release\openstory-console.exe --ip <服务器地址> --port 8484 --account <账号> --password <密码> --duration 15 > %TEMP%\tui_dbg.txt 2>&1"`

- 无账号/密码参数时弹出**登录向导**（Tab/↑↓ 切换字段，Enter 连接，密码掩码显示）
- 登录过程中弹窗选择：**性别 → 世界 → 频道 → 角色**（↑↓ 选择、Enter 确认、Ctrl+C 退出）
- `Ctrl+C` 发 `quit` 优雅登出；1 秒内再按一次强制退出
- 会话结束后留屏回顾日志（`PgUp/PgDn` 滚动），`Ctrl+C` 关闭窗口

- HP/MP 条形（比例着色）+ 数值、金币、当前地图名与坐标、日志丢弃计数、时钟

### 2.2 日志流 + 过滤页签
- 每条日志 = 时间戳 + 分类 tag + 正文；**tag 与正文全中文**（未收录的消息回退英文原文）

  - 空输入按 `Tab` 向后 / `Shift+Tab` 向前循环切换
  - 非空输入时 `Tab`/`Shift+Tab` 是补全轮换
- 滚动：`PgUp/PgDn` 或鼠标滚轮（5000 行环形缓冲，封包洪泛时丢最旧），上翻时顶部显示回滚提示

### 2.4 命令补全（Tab）
- 三级补全：命令名 → 子命令 → 动态 id/oid（NPC/怪物/放置物/规则/任务/组）
- **候选带描述**：如 `npc 100001 -- 米娅`——弹窗显示名字，选中后只填入命令本体
- NPC 数字 oid 候选排前、对话子命令在后；`↑↓` 或 `Tab`/`Shift+Tab` 轮换，`Enter` 发送
- `F1` 打开命令帮助（全命令 + 子命令 + 中文说明）

### 2.5 输入与历史
- `Enter` 发送、`↑↓` 历史（保留草稿）、`Esc` 关闭补全弹窗或清空输入
- 空输入时显示占位提示（如 `view / hunt on / chat 你好`）

## 3. 中文渲染体系

TUI 的中文能力**不依赖翻译整句**，而是建立在结构化事件之上：

### 3.1 底层：结构化字段（src/emit.rs）
bot 核心每条消息携带语义字段：
```
[击杀] oid=123 mobid=120100 → Field::Oid => 123, Field::MobId => 120100
```
- `Field` 枚举约 45 项：Oid/Cid/MobId/ItemId/NpcId/MapId/PartyId/SkillId/ReactorId/
  Id/Job/Count/Qty/Slot/Items/Equips/Skills/Hp/MaxHp/Mp/MaxMp/Exp/Level/Ap/Sp/Meso/
  Damage/Percent/Range/Targets/Channel/Selection/Value/Number/Duration/Price/Pos/
  Ground/Name/Text/World/Portal/MoveMode/AttackMode/Toggle/Until/Step/Phase/Status
- 宏语法（字段在前）：`emit_f!([Field::X => v, ...] => "英文原文", args)`
- CLI 输出英文原文**逐字节不变**；字段只服务前端

### 3.2 渲染层（crates/console-lib/src/zh.rs）
- `translate_tag()`：tag 词典（`[kill] → [击杀]`、`[member] → [成员]`…）
- `render_fields()`：字段 → 中文键值，HP/MaxHp、MP/MaxMp 自动合并为 `血量:4849/4741`
- 值翻译：开关（开/关）、移动方式（走路/传送）、攻击方式（普攻/技能/范围攻击/定点瞬击）
- id 名称解析：怪物/NPC/物品/地图/技能 id 全部查 `data/*.json` 词典（`id·名称`，未知回退 `未知`）
- `zh_body()`：无字段的固定消息整句中文化（如 `已重连频道服务器`）
- `zh_hidden()`：交互提示（选世界/选角色）由弹窗完成，日志里整条隐藏
- 渲染优先级：`zh_hidden > zh_body > 结构化字段 > 英文原文回退`

### 3.3 名称词典（data/*.json）
| 文件 | 内容 | 来源 |
|------|------|------|
| `map.json` | 地图 id → 名称 | 反编译导出 |
| `npc.json` | NPC id → 名称 | 反编译导出 |
| `mob.json` | 怪物 id → 名称 | 反编译导出 |
| `item.json` | 物品 id → 名称 | 反编译导出 |
| `skill.json` | 技能 id → 名称（526 条） | `data/Skill.img.json` 用 `examples/convert_skills.rs` 归一化生成 |

> 词典懒加载（首次查询时读盘），文件缺失时静默降级为 `未知`，不影响运行。

## 4. 快捷键一览

| 按键 | 功能 |
|------|------|
| `Tab` / `Shift+Tab` | 空输入：过滤页签向后/向前切换；有输入：补全候选轮换 |
| `↑` / `↓` | 有补全候选时轮换候选；否则历史上/下 |
| `Enter` | 发送命令 / 确认弹窗选项 |
| `Esc` | 关闭补全弹窗 → 清空输入 → 关闭帮助弹窗 |
| `PgUp` / `PgDn` / 滚轮 | 日志回滚 / 回到底部 |
| `F1` | 命令帮助（Esc 关闭） |
| `Ctrl+C` | 发 quit 优雅登出；1 秒内再按强制退出 |
| 登录向导内 | `Tab`/`Shift+Tab`/`↑↓` 切换字段，`Enter` 连接 |
| **多开专属** | |
| `Alt+↑↓` | 切换选中账号（循环）。不用 `Ctrl+↑↓`：Windows Terminal 拿它切标签页 |
| `F2` | 看板页（N 行 × 全字段；`↑↓`/`PgUp`/`PgDn` 滚动，`F2`/`Esc` 关闭） |
| `F3` | 手动重连选中账号（还在跑时只清退避计数，不踢下线） |
| `@all <命令>` | 发给全部账号 |
| `@<档案名前缀> <命令>` | 发给同前缀的一组（无命中会报错，不会误发给当前账号） |

> 多开专属键位在**运行阶段与"已结束"阶段都生效** —— 恰恰是应用整体结束后
> 最需要手动拉起某一个号。

## 5. 与 headless CLI 的对应

- 命令语法完全一致（`hunt stand on`、`rule status`、`group open money`…）
- 规则/任务/组管理：`rule status` 只列顶层（带序号多行）；`group status` 看组内全量明细（规则 when/then + 任务步骤）
- `--auto` 可在 TUI 里跑自动化（如 `--auto "hunt on"`）
- 游戏内 `#指令` 密语控制（config `chat_admins` / `--chat-admin`）在 TUI 下同样生效

## 6. 开发说明

```
crates/console/src/        ← 共享前端层（TUI 与将来的 Web 前端共用；不含 ratatui）
├── text.rs           字符/显示宽度、插入删除、折行、截断（中文算 2 列）
├── theme.rs          冒险岛配色（玻璃拟态粉色系）
├── zh.rs             中文渲染层（词典/字段/整句/隐藏规则）
├── enrich.rs         id → 中文名富化（mobid=/npcid=/itemid=）
├── logbuf.rs         环形日志缓冲（1000 行 + 折行缓存 + O(1) 交换）
├── eventq.rs         事件队列（Emitter 实现；毒化安全）
├── snapshot.rs       状态快照（渲染线程一次取全，不持锁）
├── command_spec.rs   命令表唯一数据源（补全与帮助都从它来）
└── completion.rs     补全五级决策（与解析器的一致性由测试守住）

crates/console/src/
├── main.rs           入口：终端初始化、向导、多开启动、bot 线程 + 渲染线程
├── app.rs            App 状态机：按键、补全、历史、滚动、事件轮询、拉起调度
├── ui.rs             全部界面绘制（状态栏/日志/面板/左栏账号列表/F2 看板/弹窗）
├── session.rs        单个 bot 会话（状态/队列/日志/指令通道/拉起状态）
├── sessions.rs       会话集合（选中 / `@` 目标解析 / 批量下发 / 退出条件）
├── watcher.rs        掉线自动拉起：纯状态机（退避/放弃）+ 进程级句柄
├── credentials.rs    密码双模式存储（profiles/.manager.json，默认不落盘）
├── profile.rs        档案选择屏 + 缺密码询问
└── wizard.rs         登录向导
```

- 测试：`cargo test --workspace`（949 项。含渲染回归 `crates/console/tests/render_regression.rs`
  —— 它驱动真实的 `App`+`ui::render` 并把帧缓冲 dump 成文本断言）
- 渲染线程 `try_lock` 一次取全快照，不阻塞 bot 主循环；`tick_ms` 可压到 1ms
- **多会话隔离由三层保证**（详见 [MANAGER_PLAN.md](MANAGER_PLAN.md) §2）：每个会话
  自己的事件队列（task-local emitter）、自己的 `BotState`、按 `data_dir` 共享的名字表
- 事件通道（`openstory_bot::emit`）为将来 HTTP / WebSocket 前端预留
