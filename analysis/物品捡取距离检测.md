# 捡物检测分析

## 概述

分析 CMS 79 客户端捡取物品的完整逻辑链路，以及实现全屏捡取的修改方案。

## 按键处理链

### 按键映射

```
按键释放 (a3 == 0)
  └── 按键索引 a2 对应动作类型 v20[a2]
      v20 从 dword_BDD494 + 152 复制
```

| 动作类型 | 含义 | 处理函数 |
|----------|------|----------|
| 1 | NPC 对话 | sub_954F0F |
| 2 | 坐下/起身 | sub_95308C / sub_952F1F |
| **3** | **捡取** | **sub_50D440** |
| 4-9 | 快捷栏动作 | sub_955C96 |

### 源码位置

**sub_9535F1** (0x9535F1) — 按键按下/释放总处理器。参数 `a2`=按键索引，`a3`=0 释放/1 按下。

按键释放且动作类型=3 时的调用（`0x9537F3`）：
```c
case 3:
    sub_50D440(this, player_pos);
    sub_A3C3B1(...);
    break;
```

## 核心函数：sub_50D440 (0x50D440)

遍历掉落池中所有掉落物，检查距离合法性，符合条件的发送捡取包。

### 捡取范围定义

```
0x50D4BC: lea edx, [eax-19h]    → x1 = player_x - 25  (0x19)
0x50D4C2: lea edx, [ecx-32h]    → y1 = player_y - 50  (0x32)
0x50D4C5: add eax, 19h          → x2 = player_x + 25  (0x19)
0x50D4C8: add ecx, 0Ah          → y2 = player_y + 10  (0x0A)
```

捡取范围 = 角色位置 ± 25px (X轴) / -50~+10px (Y轴)，约 50x60 像素范围。

### 遍历逻辑

```c
sub_50D440(CUserLocal *this, CPoint *player_pos) {
    // 捡取边界框
    RECT bbox;
    bbox.x1 = player_pos->x - 25;
    bbox.y1 = player_pos->y - 50;
    bbox.x2 = player_pos->x + 25;
    bbox.y2 = player_pos->y + 10;

    // 每捡一次有防刷冷却
    if (!sub_485138(30, 0))
        return;

    // 遍历 CDropPool 中所有 drop
    for (each drop in this->dropPool) {

        // -------- 跳过条件 --------

        // 1. 装备检查：如果是装备且被屏蔽列表命中，跳过
        if (drop->isEquip && !IsAllowedItem(drop->itemId))
            continue;

        // 2. 超时 + 归属检查
        if (current_time - drop->drop_time < 15000 || !drop->mobOwner) {
            // 时间不足 15 秒且有归属者时
            if (drop->ownerType == 0 && drop->ownerId != self->charId)
                continue;  // 非我所属
            if (drop->ownerType == 1 && drop->ownerId != self->partyId)
                continue;  // 非我队伍所属
        }

        // 3. 状态检查：drop 必须处于可捡取状态
        if (!drop->isPickupable)  // drop->field_29
            continue;
        if (drop->state != 3)    // drop->field_72 != STATE_PICKUPABLE
            continue;

        // 4. 落地保护：落地不足 3 秒不可捡
        if (current_time - drop->enterTime < 3000)
            continue;

        // -------- 距离检测 --------
        if (PtInRect(&bbox, drop->x, drop->y)) {  // dword_BE1734
            // 捡取！
            sub_A126C5(drop->dropId, drop->itemId, ...);
            drop->lastPickupTime = current_time;  // 防重复捡取
            return;  // ★ 只捡第一个
        }
    }
}
```

### 跳过条件详解

| 条件 | 偏移 | 说明 |
|------|------|------|
| 防刷冷却 | this + 0x1E | sub_485138检查，约30帧冷却 |
| 装备检查 | drop+48==0 | 装备需要过白名单(sub_6097AA) |
| 归属者 | drop+44==0/1 | 0=个人归属(检查CharID+32)，1=队伍归属(检查PartyID+36) |
| 可捡取标记 | drop+29==0 | 字段 field_29 |
| 状态标记 | drop+72==3 | 只有 state==3 才可捡 |
| 落地冷却 | drop+84 | current_time - drop_enter_time >= 3000 |
| 超时保护 | drop+64 | drop_time + 15000 后可捡 |
| 距离检测 | dword_BE1734 | 碰撞检测函数，检测drop坐标是否在bbox内 |

### 距离检测的精确位置

```
0x50D596: lea esi, [eax+68h]      // drop 对象 + 0x68 (结构体偏移)
0x50D599: lea ecx, [esi+0Ch]      // +0x74 → drop y 坐标 (TSecType_long)
0x50D59C: call TSecType_long_::GetData
0x50D5A1: mov [ebp-24h], eax      // [ebp-24h] = drop->y
0x50D5A6: call TSecType_long_::GetData  // drop->x (从 esi 即 drop+0x68 取)
0x50D5AB: push eax                // drop->x
0x50D5AC: push dword ptr [ebp-24h] // drop->y
0x50D5AF: lea eax, [ebp-34h]      // bbox 结构体指针
0x50D5B2: push eax
0x50D5B3: call dword_BE1734       // 碰撞检测 PtInRect(bbox, x, y)
0x50D5B9: test eax, eax           // 检测结果
0x50D5BB: jnz 0x50D5E3            // 命中 → 跳转到捡取发包逻辑
0x50D5BD: ...                     // 未命中 → 继续循环
```

## 发包函数：sub_A126C5 (0xA126C5)

构造 opcode=198 (0xC6) 的 COutPacket 发送捡取请求。

```c
sub_A126C5(CUserLocal *this, CPoint *playerPos, int dropId, int itemId) {
    if (!CanPickup())
        return;

    COutPacket pkt(198);           // 捡取请求 opcode
    pkt.Encode1(fieldPlayerId);    // sub_4376F2() + 300
    pkt.Encode4(get_update_time());
    pkt.Encode2(playerPos->x);     // ★ 发的是玩家坐标，不是物品坐标！
    pkt.Encode2(playerPos->y);     // ★ 发的是玩家坐标，不是物品坐标！
    pkt.Encode4(dropId);           // 掉落物 ID
    pkt.Encode4(itemId);           // 物品 ID
    CClientSocket::SendPacket(&pkt);

    this->pickupCooldown = 1;      // field_8328
    this->lastPickupTime = now();  // field_8332
}
```

> **重要：** `a2` 参数是 `sub_50D440` 传入的 `player_pos`（玩家坐标结构体指针），**不是**掉落物的坐标。
> 物品坐标仅在客户端距离检测（`dword_BE1734`）中使用，不入包。
> 所以全屏捡取后，服务端收到的是玩家原始位置，如果玩家离物品太远，服务端可能拒绝捡取。

发包后服务端验证通过会广播 0x111(OnDropLeaveField) 给所有玩家，type=0 表示当前玩家捡取成功。

## 全屏捡取修改方案

### 方案一：修改捡取边界框（4个立即数）

在 `sub_50D440` 开头将捡取范围改为全图：

| 地址 | 原来 | 改为 | 说明 |
|------|------|------|------|
| `50D4BC` | `lea edx, [eax-19h]` (eax-25) | `lea edx, [eax-0x2710]` (eax-10000) | x1 |
| `50D4C2` | `lea edx, [ecx-32h]` (ecx-50) | `lea edx, [ecx-0x2710]` (ecx-10000) | y1 |
| `50D4C5` | `add eax, 19h` (eax+25) | `add eax, 0x2710` (eax+10000) | x2 |
| `50D4C8` | `add ecx, 0Ah` (ecx+10) | `add ecx, 0x2710` (ecx+10000) | y2 |


### 方案二：跳过距离检测（推荐，改动最小）

将 `test eax,eax / jnz` 改为无条件 `jmp`：

```
0x50D5B9: 85 C0 75 26    (test eax,eax; jnz 50D5E3)
                   ↓
0x50D5B9: EB 28 90 90    (jmp 50D5E3; nop; nop)
```


原理：`dword_BE1734` 函数仍然被调用（兼容性好），但返回值被忽略，通过无条件跳转直接执行捡取发包逻辑。

### 方案三：跳过落地保护（IDA验证可行）

将 `0x50D594` 处的 `jl`（时间不足3000ms时跳过）改为 NOP：

```
0x50D594: 7C 30    (jl short loc_50D5C6)
               ↓
0x50D594: 90 90    (nop; nop)
```


**影响**：仅禁用落地3秒保护这一个时间门控，其余所有条件（归属、状态、距离检测）保持不变。

### 方案四：单次捡取所有物品（IDA验证可行）

默认 `sub_50D440` 捡到第一个就 return。想一次捡全部需要改为 continue——捡取后不退出函数，继续遍历下一个掉落物。

**Patch 方法**：将 `0x50D625` 处的 `call sub_511769` 改为 `jmp` 跳转到非拾取路径的清理代码，该路径会释放当前 drop 后自然跳回循环入口 `0x50D4DF` 继续遍历。

```
0x50D625: E8 3F 41 00 00    (call sub_511769)
                   ↓
0x50D625: E9 AC FF FF FF    (jmp 0x50D5D6)
```


**原理**：跳转到 `0x50D5D6`（非拾取路径的清理代码段），执行 `call sub_511769` + `mov [ebp-18h], ebx` + `jmp loc_50D4DF`，自然跳回循环入口继续遍历。

**风险**：低。堆栈平衡、引用计数、循环终止条件均不受影响。捡取发包函数 `sub_A126C5` 内部已有 `pickupCooldown = 1` 防刷限制，连续捡取由该冷却控制节奏。

### 方案五：捡取时同步物品坐标到人物坐标（防服务端距离检测）

全屏捡取后，服务端收到的发包中仍是玩家原始坐标。若服务端校验玩家与物品的距离，会因距离过远拒绝捡取。

**思路**：在距离检测通过后、调用 `sub_A126C5` 发包之前，将玩家坐标修改为物品坐标，使服务端判定玩家在物品位置。

#### 物品坐标位置

| 什么 | 位置 | 说明 |
|------|------|------|
| drop 对象指针 | `[ebp-18h]` | 整个函数周期内持久保存 |
| 坐标结构体基址 | `esi` (自 `0x50D596: lea esi,[eax+68h]` 起) | `esi = drop + 0x68` |
| 物品 X | `TSecType_long` 在 `drop+0x68` (即 `esi+0x00`) | 需调 `GetData` 解码为 int32 |
| 物品 Y | `TSecType_long` 在 `drop+0x74` (即 `esi+0x0C`) | 需调 `GetData` 解码为 int32 |

`TSecType_long::GetData` 是 `__thiscall`（`ecx=this`），返回值在 `eax`。

#### 人物坐标写入位置

人物基址：`[dword_BDD490]`（`0x00BDD490`）

| 偏移 | 类型 | 说明 |
|------|------|------|
| `+0xEE8` | int | 记录 X — 服务端校验坐标 |
| `+0xEEC` | int | 记录 Y |
| `+0xEF0` | int | X 副本2 |
| `+0xEF4` | int | Y 副本2 |
| `+0x28F8` | int | 真实 X（移动处理器写入） |
| `+0x28FC` | int | 真实 Y |
| `+0x28F0` | int | 移动标志（设为 1 触发坐标同步） |

详见 [人物位置-移动更新.md](人物位置-移动更新.md)。

#### 注入时机

在 `0x50D5E3`（捡取发包路径起点）处通过 code cave 注入：

```
距离检测通过 (0x50D5BB: jnz 0x50D5E3)
  │
  ├── [Code Cave 入口]  ↓ jmp
  │     ├─ esi = drop+0x68（坐标结构体，此时仍有效）
  │     ├─ 调 TSecType_long::GetData 读 X
  │     ├─ 调 TSecType_long::GetData 读 Y
  │     ├─ player = [0xBDD490]
  │     ├─ 写入 player+0xEE8 = X, player+0xEEC = Y
  │     ├─ 写入 player+0x28F8 = X, player+0x28FC = Y
  │     └─ 写入 player+0x28F0 = 1（移动标志）
  │
  └── [返回 0x50D5E8] → 继续原捡取路径 → call sub_A126C5
```


> **注意**：`0x50D5E3` 处的原始 5 字节指令需要从 IDA 中确认后填入脚本的 `db` 部分。
> `TSecType_long::GetData` 地址 `0x429944` 已验证，直接可用。

> **注意**：如果服务端验证距离，客户端修改无效。此时只能修改服务端捡取逻辑或用私服。
> 方案五的前提是服务端信任客户端上报的坐标（大多数私服/老版本如此）。
