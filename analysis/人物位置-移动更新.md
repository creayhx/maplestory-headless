# 冒险岛 人物移动更新机制

## 基本信息

| 项目 | 内容 |
|------|------|
| 目标进程 | MapleStory.exe (32-bit) |
| 基址 | 0x400000 (无 ASLR) |
| 人物基址 | `dword_BDD490` (0x00BDD490) |

---

## 核心概念

人物坐标存在**三个层级**：

```
子对象 (源坐标)  ──→  移动处理器 (28F8/28FC)  ──→  记录坐标 (EE8/EEC)
     ↓                       ↓                        ↓
   真实坐标              移动中会变化            服务器校验副本(只读)
```

---

## 人物结构体偏移

人物对象基址来自 `[0x00BDD490]`，以下是关键偏移：

| 偏移 | 类型 | 说明 |
|------|------|------|
| `+0xEE8` | int | X 记录坐标 — 只读副本，服务器会校验该值 |
| `+0xEEC` | int | Y 记录坐标 — 只读副本 |
| `+0xEF0` | int | X 副本2 (与 0xEE8 同时更新) |
| `+0xEF4` | int | Y 副本2 |
| `+0xF28` | ptr | → **子对象指针**，包含源位置数据 |
| `+0x28F0` | int | **移动处理标志**：0=无移动，1=允许移动 |
| `+0x28F4` | int | 移动状态/方向 |
| `+0x28F8` | int | **Teleport 真实 X 坐标参数** — 写入 + 设置 28F0=1 后触发传送；**移动完成后直接归零，不能作为人物当前坐标读取** |
| `+0x28FC` | int | **Teleport 真实 Y 坐标参数** — 同上 |
| `+0x2900` | int | 移动进度值 (递减到 ≤0 时触发同步) |
| `+0x2904` | int | 移动边界值 |

## 移动更新流程

### 写入真实坐标 (移动处理器)

```
[0x96423F] mov [esi+0x28F8], ebx      ; 设置 Teleport 真实 X
[0x964263] mov [esi+0x28FC], edi      ; 设置 Teleport 真实 Y
[0x964247] mov [esi+0x28F0], 1        ; 设置移动标志
[0x96425A] mov [esi+0x2900], eax      ; 设置移动进度
```

> ⚠️ **关键理解：** `28F8/28FC` 是 **Teleport 的参数写入区**，不是人物当前坐标。  
> 流程是：**写入目标坐标 → 设置 28F0=1 → 触发传送 → 坐标同步至 EE8/EEC → 28F8/28FC 自动归零**。  
> 移动完成后这两个值直接变回 `0`，**不能用作读取人物当前位置**。  
> 读取人物坐标请使用 `EE8/EEC`（服务器记录值）。

移动处理器在以下时机触发：
- 物理引擎更新玩家位置时
- 收到服务器移动确认包时（header 0x7A7）

### 同步到记录坐标 (坐标副本更新)

```
[0x9552F0] push ebx
           push esi
           mov esi, ecx              ; this = 人物对象
           call sub_994C7A
           cmp [esi+0x28F0], 0       ; 检查移动标志
           je skip                   ; 标志=0 则跳过
           mov eax, [esi+0x28FC]     ; 读取真实 Y
           mov ecx, [esi+0x28F8]     ; 读取真实 X
           ...
           mov [esi+0x0EE8], eax     ; → 记录 X
           mov [esi+0x0EEC], eax     ; → 记录 Y
           mov [esi+0x0EF0], eax     ; → 副本2 X
           mov [esi+0x0EF4], eax     ; → 副本2 Y
```

### 子对象投影 (UE 引擎坐标投射)

```
[0x9C1581] mov [ebx], eax            ; 将计算结果写入 [ebx] = 人物+0xEE8
```

`MapleStory.exe+5C1581` 所在函数从 `[player+0xF28]` 指向的子对象中读取位置数据，
进行浮点运算（三角函数 / 坐标投影），将计算结果写入 `player+0xEE8`。

该函数每次游戏循环 tick 都会被调用，持续地将子对象中的坐标投影到记录坐标。

---

## 关键函数地址

| 地址 | 函数说明 |
|------|---------|
| `0x9552F0` | 坐标同步函数 — 从 28F8/28FC 复制到 EE8/EEC (需要 28F0=1) |
| `0x9C1500` | 坐标投射函数 — 从子对象读取并写入 EE8 |
| `0x964200` | 移动处理器 — 更新 28F8/28FC 并设置 28F0=1 |
| `0x9C1581` | `mov [ebx],eax` — 写入 EE8 的指令点 |

## 实战：实现任意位置移动 (Teleport)

要强制将人物传送到目标位置 (targetX, targetY)，需要：

1. **设置移动标志**
   ```
   [[0x00BDD490]] + 0x28F0 = 1
   ```

2. **写入 Teleport 目标坐标**
   ```
   [[0x00BDD490]] + 0x28F8 = targetX
   [[0x00BDD490]] + 0x28FC = targetY
   ```

3. **设置移动进度**（触发同步到 EE8）
   ```
   [[0x00BDD490]] + 0x2900 = 0   ; 使同步条件成立
   ```

4. 等待下一帧，坐标同步函数会自动将 28F8/28FC 复制到 EE8/EEC

5. **传送完成后 28F8/28FC 自动归零**，此时人物当前坐标以 `EE8/EEC` 为准

> ⚠️ **重要：** `28F8/28FC` 是 **Teleport 的参数写入区**，设置完成后立即触发传送，传送完成后直接重置为 `0`。  
> - **写入用途：** 设置 Teleport 目标坐标
> - **读取用途：** ❌ **不能作为人物当前坐标读取**（归零后不准）
> - **正确读取：** 使用 `EE8` (X) / `EEC` (Y) — 服务器记录值

**注意：** 该方案直接操作内存坐标。能否被服务器接受取决于服务器的移动检测逻辑。
部分服务器会校验客户端发送的移动包与内存坐标是否一致。

## 子对象结构 (源坐标)

子对象由 `[[0x00BDD490] + 0xF28]` 指向，包含原始位置数据：

| 偏移 | 类型 | 说明 |
|------|------|------|
| `+0x00` | ptr | vtable (0x00B0CAC0) |
| `+0x04` | int | 计数 (通常为 7) |
| `+0x08` | ptr | 回指人物对象 |
| `+0x0C` | int | 标志位 (通常为 1) |
| `+0x14` | - | 位置数据块起始 |
| `+0x24` | - | 位置数据块延续 |
| `+0x2C` | - | 坐标数据区 |
| `+0x3C` | - | 坐标关联值 |
| `+0x74` | - | 坐标数据区2 |
| `+0x84` | - | 坐标关联值2 |
| `+0x9C` | - | 其他关联值 |

> **注意：** 子对象内的位置数据是**加密存储**的，每 16 字节为一组加密块。
> 函数 `DecryptEncodedDouble__cdecl (0x548806)` 负责解密，返回 `double`。

---

## 加密/解密说明

### DecryptEncodedDouble__cdecl (0x548806)

人物属性（包括子对象中的位置数据）均为加密存储。解密函数由两段组成：

```
[0x548806] DecryptEncodedDouble__cdecl(a1, a2)
→ a1 = 加密数据指针 (16字节)
→ a2 = 校验和
← 返回解密后的 double
```

**加密数据布局 (16字节)：**

| 偏移 | 说明 |
|------|------|
| `+0x00` | 加密 dword0 (解密后作为 double 低位) |
| `+0x04` | 加密 dword1 (解密后作为 double 高位) |
| `+0x08` | 密钥 dword0 |
| `+0x0C` | 密钥 dword1 |

**解密过程：**

```
ROL(key, 5) XOR encrypted → decrypted_dword
```

1. 读取密钥 dword (位置+0x08)
2. `ROL(密钥, 5)` — 自定义左旋转 5 位 (`rol_custom__cdecl (0xA705FB)`)
3. XOR 加密 dword (位置+0x00) 得到明文
4. 重复处理第二组 (位置+0x04 / +0x0C)
5. 两个解密后的 dword 合并为 8 字节 double
6. 校验和匹配验证

### IDA 已添加注释

```
0x548806 → DecryptEncodedDouble__cdecl  (解密编码的double值)
0xA705FB → rol_custom__cdecl            (自定义左旋转 ROL)
```
