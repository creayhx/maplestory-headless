# 多开器 — 双开功能分析报告

> 分析目标：`第三方多开工具`（2019-01-27 编译，32位 MFC 应用）
> MD5: `0a81f2445ede63e5a60daad6b64e5c4b`

---

## 一、功能概述

多开器是一个专门针对 **MapleStory（冒险岛）** 的多开工具，通过绕过游戏的单实例检测机制（命名互斥体），允许用户在同一台机器上同时运行多个 MapleStory 客户端实例。

---

## 二、核心逻辑流程

```
用户点击"双开"按钮
    │
    ▼
sub_402464 / sub_401045
    │
    ├─ 搜索 MapleStory.exe / Maplestory.exe 进程
    │   (CreateToolhelp32Snapshot + Process32First/Next)
    │
    ├─ 存在? ──否──▶ 显示 "状态:无游戏运行" / "请运行游戏!"
    │
    └─ 是: 遍历每个进程实例
         │
         ┌─────────────────────────────────────────────────────────┐
         │  Phase 1 — 打开目标进程                                 │
         │  OpenProcess(PROCESS_ALL_ACCESS, pid)  → hProcess       │
         └─────────────────────────────────────────────────────────┘
         │
         ┌─────────────────────────────────────────────────────────┐
         │  Phase 2 — 暴力扫描句柄空间 (sub_401DD1)                 │
         │                                                        │
         │  for handleValue = 4; handleValue < 0x10000; += 4:     │
         │    NtDuplicateObject(hProcess, handleValue, hSelf,      │
         │                      &dup, 0, 0, SAME_ACCESS)           │
         │    └─ 成功? → NtQueryObject(dup, ObjectNameInfo)        │
         │                → 存储 (handleValue, 对象名) 到映射表     │
         │                → CloseHandle(dup)                       │
         └─────────────────────────────────────────────────────────┘
         │
         ┌─────────────────────────────────────────────────────────┐
         │  Phase 3 — 搜索目标互斥体 (sub_401B20 内层循环)           │
         │                                                        │
         │  for each (entry in handleMap):                        │
         │    memicmp(entry.name, "WvsClientMtx")                 │
         │    memicmp(entry.name, "zhuzhuClientMtx")              │
         │    memicmp(entry.name, "WAxmxdClientMtx")              │
         └─────────────────────────────────────────────────────────┘
         │
         ┌─────────────────────────────────────────────────────────┐
         │  Phase 4 — 窃取互斥体句柄                                │
         │  DuplicateHandle(hProcess, hMutex, hSelf, &dup,         │
         │                  0, 0, SAME_ACCESS | CLOSE_SOURCE)      │
         │  → MapleStory 进程句柄表中删除 WvsClientMtx              │
         │  → 互斥体引用计数归零 → 新实例可创建同名互斥体             │
         │  → 显示 "多开成功!"                                     │
         └─────────────────────────────────────────────────────────┘
```

## 三、关键函数分析

### 3.1 `sub_401045` — 互斥体绕过核心 (0x401045)

**入口条件**：检测到 `Maplestory.exe`（小写）正在运行

**执行流程**：
1. 分配动态数组结构
2. 调用 `sub_401379` 搜索 `Maplestory.exe`，获取所有实例的 PID 列表
3. 若找到进程：
   - 遍历每个 PID
   - 对每个 PID 依次调用 `sub_401B20` 处理 `WvsClientMtx`、`zhuzhuClientMtx`、`WAxmxdClientMtx`
   - `sub_401B20` 内部完成：打开进程 → 暴力扫描句柄 → 匹配互斥体名 → DuplicateHandle 窃取
   - 任意互斥体处理成功 → 显示 **"多开成功!"**
4. 若未找到进程 → 弹 MessageBox **"请运行游戏!"**

**伪代码**：
```
alloc array
find_process("Maplestory.exe", &array)
if process_count > 0:
    for each pid in array:
        result = steal_mutex(pid, "WvsClientMtx")      // sub_401B20
        if result: show("多开成功!")
        result = steal_mutex(pid, "zhuzhuClientMtx")
        if result: show("多开成功!")
        result = steal_mutex(pid, "WAxmxdClientMtx")
        if result: show("多开成功!")
    show("多开成功!")
else:
    show("请运行游戏!")
```

### 3.2 `sub_402464` — 状态感知逻辑 (0x402464)

**入口条件**：检测到 `MapleStory.exe`（驼峰）状态

**执行流程**：
1. 搜索 `MapleStory.exe` 进程
2. 根据进程存在与否显示不同的状态提示

**伪代码**：
```
find_process("MapleStory.exe")
if process_exists:
    show_status("状态:游戏运行中")
else:
    show("状态:无游戏运行")
```

### 3.3 `sub_401B20` — 互斥体窃取处理器 (0x401B20)

**作用**：这是双开的核心实现。**不是通过 OpenMutex/CreateMutex，而是通过句柄窃取（Handle Stealing）技术**。

**调用关系**：
```
sub_401B20(pid, &mutex_name)
  ├─ sub_401CF2(pid)       → 打开目标进程
  ├─ sub_401DD1(hProcess) → 暴力扫描句柄空间
  └─ 内层循环              → 匹配 + 窃取
```

#### 3.3.1 打开目标进程 — `sub_401CF2` (0x401CF2)

内部解析函数表索引 4（对应 `OpenProcess`）：

| 汇编 | 说明 |
|------|------|
| `push pid` | 目标进程 ID |
| `push 0` | `bInheritHandle = FALSE` |
| `push 0x1F0FFF` | `dwDesiredAccess = PROCESS_ALL_ACCESS` |
| `mov eax, 4` | 函数表索引 4 = OpenProcess |
| `call sub_40276D` | 动态解析并调用 |

返回 `hProcess`（目标进程句柄）。

#### 3.3.2 暴力扫描句柄空间 — `sub_401DD1` (0x401DD1)

该函数不知道 MapleStory 进程中 `WvsClientMtx` 的具体句柄值（如 0x1A4），因此**从 4 到 0x10000 逐一遍历所有可能的句柄值**：

| 汇编地址 | 指令 | 说明 |
|----------|------|------|
| `0x401E7E` | `add [ebp+var_C], 4` | **当前句柄值 += 4**（句柄值 4 字节对齐） |
| `0x401E2D` | `mov eax, 5` | 函数表索引 5 |
| `0x401E32` | `call sub_40276D` | → **NtQuerySystemInformation**？ |

等等——让我纠正之前的分析。实际看反汇编更仔细：

**内部流程还原**：

```c
// sub_401DD1(hProcess, &outputArray) 伪代码

// 函数表索引 5 → 某个初始化的系统查询
DWORD maxHandleCount = FunctionTable[5](hProcess);
// 可能是 NtQueryInformationProcess(ProcessHandleCount) 获取进程句柄数

DWORD successCount = 0;
DWORD currentHandle = 0;     // var_C

while (successCount < maxHandleCount && currentHandle < 0x10000) {
    currentHandle += 4;      // 步长 4
    
    // 函数表索引 6 → GetCurrentProcess()
    // 函数表索引 7 → NtDuplicateObject
    HANDLE dupHandle;        // var_10
    NTSTATUS status = NtDuplicateObject(
        hProcess,               // arg_0
        (HANDLE)currentHandle,  // var_C (猜测的句柄值)
        GetCurrentProcess(),    // 函数表索引 6
        &dupHandle,             // &var_10
        0, 0,
        DUPLICATE_SAME_ACCESS   // 选项 = 2
    );
    
    if (NT_SUCCESS(status)) {
        // currentHandle 是一个有效句柄！
        // 分配缓冲区 → sub_402ED0 分配 0x2000 字节
        // 函数表索引 8 → NtQueryObject
        WCHAR nameBuffer[0x1000];    // 0x2000 字节
        NtQueryObject(
            dupHandle,              // 复制的句柄
            ObjectNameInformation,  // 查询对象名
            nameBuffer,
            sizeof(nameBuffer),
            &returnLen
        );
        
        // 存储映射关系
        outputArray[successCount].handleValue = currentHandle;
        outputArray[successCount].nameW = wcsdup(nameBuffer);
        successCount++;
        
        CloseHandle(dupHandle);
    }
    
    // 边界保护
    if (currentHandle >= 0x10000) break;  // 0x401E5D
}
```

**关键常量说明**：
| 常量值 | 含义 |
|--------|------|
| `0x4` | 句柄值起始（Windows 句柄从 4 开始，步长 4） |
| `0x10000` | 句柄值上限（足够覆盖所有进程句柄） |
| `0x2000` | NtQueryObject 缓冲区大小（8KB，足够容纳对象路径名） |
| `DUPLICATE_SAME_ACCESS = 2` | 按原始权限复制句柄 |

#### 3.3.3 匹配 + 窃取 — 内层循环

句柄空间扫描完成后，`outputArray` 里存储了 MapleStory 进程中所有有效句柄的 (值, 内核对象名) 对。随后进入匹配循环：

**匹配**：
```c
// sub_401B20 内层循环
for each (entry in outputArray) {
    // EBX = sub_402AF0 → sub_402990 → _memicmp(entryName, mutexName)
    // sub_402785(4, entryName, ..., mutexName, ...)
    if (sub_402AF0_callback(entry.name, "WvsClientMtx")) {
        // 命中！entry.handleValue 就是 WvsClientMtx 的句柄值
        targetHandleValue = entry.handleValue;
        break;
    }
    // 同样检查 "zhuzhuClientMtx" 和 "WAxmxdClientMtx"
}
```

**窃取**：
```c
// sub_402352(hProcess, targetHandleValue)
// 函数表索引 6 → GetCurrentProcess()  (0x40236A, eax=6)
// 函数表索引 7 → DuplicateHandle       (0x4023A3, eax=7)

DuplicateHandle(
    hProcess,               // MapleStory 进程
    (HANDLE)targetHandleValue, // WvsClientMtx 句柄值
    GetCurrentProcess(),    // 多开器自身
    &stolenHandle,          // 接收窃取的句柄
    0,                      // 不请求新权限
    0,                      // 不设置继承
    DUPLICATE_SAME_ACCESS | DUPLICATE_CLOSE_SOURCE  // 选项 = 2 | 1 = 3
);

// 关键: DUPLICATE_CLOSE_SOURCE (1) 会关闭源进程中的源句柄！
// MapleStory 进程从此失去对 WvsClientMtx 的引用
```

**函数表索引汇总**：

| 索引 | API 函数 | 调用位置 |
|------|----------|----------|
| 3 | `CloseHandle` | `sub_402352` 清理 |
| 4 | `OpenProcess` | `sub_401CF2` |
| 5 | `NtQueryInformationProcess` (推测) | `sub_401DD1` 开头 |
| 6 | `GetCurrentProcess` | `sub_401DD1`、`sub_402352` |
| 7 | `NtDuplicateObject` | `sub_401DD1` 扫描 |
| 7 | `DuplicateHandle` | `sub_402352` 窃取 |
| 8 | `NtQueryObject` | `sub_401DD1` 获取对象名 |

### 3.4 `sub_401379` — 进程查找器 (0x401379)

**作用**：根据进程名枚举系统进程

**调用链**：
```
CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)
    → Process32First(hSnapshot, &pe32)

```

## 四、互斥体体系详解

### 4.1 MapleStory 的单实例机制

MapleStory（Nexon 系游戏）使用**命名内核对象**防止多开：

- 游戏启动时调用 `CreateMutex(NULL, FALSE, "WvsClientMtx")`
- 若互斥体已存在（`GetLastError() == ERROR_ALREADY_EXISTS`），游戏退出
- 利用内核对象命名空间的全局可见性实现跨进程检测

### 4.2 多开器的绕过策略（Handle Stealing 技术）

| 阶段 | 步骤 | Windows API | 代码位置 |
|------|------|-------------|----------|
| 进程枚举 | 1. 遍历系统进程 | `CreateToolhelp32Snapshot` / `Process32First/Next` | `sub_401379` |
| 打开目标 | 2. 以最大权限打开 MapleStory | `OpenProcess(PROCESS_ALL_ACCESS)` | `sub_401CF2` (函数表索引 4) |
| **暴力扫描** | **3. 遍历所有可能的句柄值 (4~0x10000)** | **`NtDuplicateObject(hProcess, handleValue, ...)`** | **`sub_401DD1`** (函数表索引 7) |
| | **4. 探测成功 → 查询内核对象名** | **`NtQueryObject(dupHandle, ObjectNameInformation)`** | **`sub_401DD1`** (函数表索引 8) |
| 匹配 | 5. 在内核对象名中搜索互斥体名 | `_memicmp` 字符串比较 | `sub_402AF0` → `sub_402990` |
| **窃取** | **6. 从目标进程强行移除互斥体句柄** | **`DuplicateHandle(hProcess, hMutex, ..., DUPLICATE_CLOSE_SOURCE)`** | **`sub_402352`** (函数表索引 7) |
| 完成 | 7. 原始进程失去互斥体引用 | 内核自动清理引用计数 | — |

#### 技术原理详解

**核心问题**：如何把 "WvsClientMtx"（一个字符串）映射到 MapleStory 进程句柄表中的一个数值（如 0x1A4）？

Windows 没有提供"根据对象名查句柄值"的 API。该工具采用的解决方案是**暴力扫描 + 试探**：

```
针对每个猜测的句柄值 (4, 8, C, 10, ..., FFFC):
  尝试 NtDuplicateObject 复制到自身
  └─ 复制成功 → 说明该值是目标进程的一个有效句柄
     └─ NtQueryObject 读取内核对象全路径名
        └─ memicmp 匹配 "\BaseNamedObjects\WvsClientMtx"
           └─ 命中 → 得到句柄值 (如 0x1A4)
```

**窃取的关键**：`DuplicateHandle` 的 `DUPLICATE_CLOSE_SOURCE` 标志（值为 1）会在复制句柄后**关闭源进程中的源句柄**。效果等价于：

```
MapleStory 进程: CloseHandle(hWvsClientMtx)  ← 强制关闭
```

该互斥体的引用计数归零，新启动的游戏实例调用 `CreateMutex("WvsClientMtx")` 时不再返回 `ERROR_ALREADY_EXISTS`，从而绕过单实例检测。

**技术分类**：✅ **纯 Win32 API 调用**（非内存修改/非 Hook/非 DLL 注入/非驱动级操作）

### 4.3 涉及的所有互斥体

| 互斥体名 | 地址 | 说明 |
|---|---|---|
| `WvsClientMtx` | `0x480B8F` | **原始 MapleStory 互斥体** — 核心目标 |
| `zhuzhuClientMtx` | `0x480BA6` | 变体（zhuzhu = 猪猪客户端） |
| `WAxmxdClientMtx` | `0x480BB6` | 变体（WAxmxd 客户端） |

## 七、备注

- 子函数 `sub_401045` 和 `sub_402464` 在编译后的二进制中无显式 CALL 引用（通过 MFC 消息映射表分发的函数指针），属于 MFC 标准的事件分发模式
- 0x52010001 是自定义的注册窗口消息，用于多开器内部通信
- 该工具仅处理 MapleStory 系列的互斥体检测，不涉及其他反作弊/反多开机制
