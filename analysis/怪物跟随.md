# 怪物跟随 — 玩家自动瞬移到怪物位置

## 功能效果

启用后，玩家角色每 100ms 自动瞬移到地图上第一个怪物的当前位置，实现"跟随怪物"效果。

---

## 实现原理

### 核心逻辑

```
每 100ms:
  1. 读取怪物池 → 遍历 ZArray → 找到第一个有效怪物
  2. 读取怪物的世界坐标 (mob+0x4C4/0x4C8)
  3. 写入玩家的传送字段 (player+0x28F8/28FC)
  4. 设置移动标志 (player+0x28F0 = 1)
  5. 设置移动进度 (player+0x2900 = 0) 触发立即同步
```

### 关键地址

| 地址/表达式 | 类型 | 说明 |
|------------|------|------|
| `[0x00BDD490]` | ptr | 玩家对象基址 (CUserLocal*) |
| `[0x00BDD49C]` | ptr | 怪物池指针 (CMobPool*) |
| `pool + 0x28` | ptr | ZArray 第一个怪物槽 |
| `slot + 0x04` | ptr | 怪物对象指针 (CMob*) |
| `slot - 0x0C` | int | 下一个槽的偏移量 (ZArray 链表) |
| `mob + 0x174` | int | 怪物 ID 明文 (用于验证) |
| `mob + 0x4C4` | int | **怪物 X 坐标** (无 CRC 保护) |
| `mob + 0x4C8` | int | **怪物 Y 坐标** (无 CRC 保护) |
| `player + 0x28F0` | int | 移动触发标志 (设 1 触发传送) |
| `player + 0x28F8` | int | 传送目标 X |
| `player + 0x28FC` | int | 传送目标 Y |
| `player + 0x2900` | int | 移动进度 (设 ≤0 触发坐标同步) |
| `player + 0xEE8` | int | 玩家当前 X (只读) |
| `player + 0xEEC` | int | 玩家当前 Y (只读) |

## 数据结构

### CMobPool (怪物池)

```
[0x00BDD49C] → CMobPool*
  ├─ +0x00: vtable
  ├─ +0x04: ZList sentinel
  ├─ +0x0C: 怪物数量 (int)
  ├─ +0x28: ZArray 第一个怪物槽 → 遍历入口
  └─ +0x5C: 当前交互目标指针
```

### ZArray 怪物槽遍历

```c
slot = *[pool + 0x28];  // 第一个槽

while (slot != NULL) {
    mobPtr = *[slot + 4];   // CMob* 指针
    if (mobPtr != NULL) {
        // 处理怪物 ...
    }
    
    next_offset = *[slot - 12];  // 下一个槽的偏移量
    if (next_offset != 0)
        slot = next_offset + 16;
    else
        break;
}
```

### CMob 关键偏移

```
CMob (this = mobPtr):
  +0x174    int    怪物ID (明文, 用于验证怪物有效性)
  +0x4C4    int    X坐标 (无CRC保护, 可直接读写)
  +0x4C8    int    Y坐标 (无CRC保护, 可直接读写)
  +0x4CC    short  X坐标 short版 (入场时服务端下发)
  +0x4D0    short  Y坐标 short版 (入场时服务端下发)
  +0x178    ptr    CPhysical子对象指针 (含加密坐标)
```

> **注意:** mob+0x4C4/4C8 来源于入场时服务端下发的 short 坐标符号扩展为 int。怪物移动时游戏物理系统会更新这些值，因此它们反映的是怪物**实时世界坐标**。

### CUserLocal 玩家传送字段

```
CUserLocal (this = [0x00BDD490]):
  +0x28F0    int    移动触发标志
                      0 = 无移动
                      1 = 触发传送/移动 (写入后待处理)
  +0x28F4    int    移动方向/状态
  +0x28F8    int    传送目标 X  (写入后由同步函数读取并归零)
  +0x28FC    int    传送目标 Y  (同上)
  +0x2900    int    移动进度值 (递减到 ≤0 时同步坐标到 EE8/EEC)
  +0x2904    int    移动边界值
  +0xEE8     int    玩家当前位置 X (只读, 服务器记录值)
  +0xEEC     int    玩家当前位置 Y (只读)
  +0xF28     ptr    → 子对象指针 (源坐标)
```

### 传送触发流程

```
写入 [player+0x28F8] = targetX
写入 [player+0x28FC] = targetY
写入 [player+0x28F0] = 1
写入 [player+0x2900] = 0

  ↓ (下一帧)
  
sub_9552F0 (坐标同步函数) 被调用:
  if [player+0x28F0] == 1 && [player+0x2900] <= 0:
    读取 [player+0x28F8] → 写入 [player+0xEE8] (X)
    读取 [player+0x28FC] → 写入 [player+0xEEC] (Y)
    [player+0x28F8] = 0
    [player+0x28FC] = 0
    [player+0x28F0] = 0
```

## 实现方案对比

### 方案 A: Lua 定时器 (推荐, 已验证可行)

用 CE Lua Engine 的 `createTimer` 每 100ms 执行一次：

```lua
local timer = createTimer(nil)
timer.Interval = 100
timer.OnTimer = function()
    local playerBase = readInteger(0x00BDD490)
    if not playerBase or playerBase < 0x10000 then return end
    
    local poolAddr = readInteger(0x00BDD49C)
    if not poolAddr or poolAddr < 0x10000 then return end
    
    local slot = readInteger(poolAddr + 0x28)
    if not slot or slot < 0x10000 then return end
    
    while slot and slot > 0x10000 do
        local mobPtr = readInteger(slot + 4)
        if mobPtr and mobPtr > 0x10000 then
            local mobId = readInteger(mobPtr + 0x174)
            if mobId and mobId > 0 then
                local mobX = readInteger(mobPtr + 0x4C4)
                local mobY = readInteger(mobPtr + 0x4C8)
                
                writeInteger(playerBase + 0x28F8, mobX)
                writeInteger(playerBase + 0x28FC, mobY)
                writeInteger(playerBase + 0x28F0, 1)
                writeInteger(playerBase + 0x2900, 0)
                return  -- 只跟随第一个怪物
            end
        end
        
        local nextOff = readInteger(slot - 12)
        if nextOff and nextOff ~= 0 then
            slot = nextOff + 16
        else
            break
        end
    end
end
timer.Enabled = true
```

### 方案 B: AA 代码洞穴 (Hook 坐标同步函数)

Hook `MapleStory.exe+9552F0` (sub_9552F0 函数入口)，在该函数执行前注入遍历怪物并传送玩家的逻辑。

**Hook 点**: `0x9552F0` — 坐标同步函数 (CUserLocal 的成员函数，ecx = player)
**覆盖**: 6 字节 (5 字节 jmp + 1 字节 nop)
**返回**: `0x9552F9` (原始 cmp 指令)

## 在其他程序中实现

### C++ 伪代码

```cpp
// 假设通过 ReadProcessMemory / WriteProcessMemory 操作目标进程

// 1. 读取玩家基址
DWORD playerBase;
ReadProcessMemory(hProcess, (LPCVOID)0x00BDD490, &playerBase, 4, NULL);

// 2. 读取怪物池
DWORD poolPtr;
ReadProcessMemory(hProcess, (LPCVOID)0x00BDD49C, &poolPtr, 4, NULL);

// 3. 遍历怪物 ZArray
DWORD slot;
ReadProcessMemory(hProcess, (LPCVOID)(poolPtr + 0x28), &slot, 4, NULL);

while (slot > 0x10000) {
    DWORD mobPtr;
    ReadProcessMemory(hProcess, (LPCVOID)(slot + 4), &mobPtr, 4, NULL);
    
    if (mobPtr > 0x10000) {
        int mobId;
        ReadProcessMemory(hProcess, (LPCVOID)(mobPtr + 0x174), &mobId, 4, NULL);
        
        if (mobId > 0) {
            // 读取怪物坐标
            int mobX, mobY;
            ReadProcessMemory(hProcess, (LPCVOID)(mobPtr + 0x4C4), &mobX, 4, NULL);
            ReadProcessMemory(hProcess, (LPCVOID)(mobPtr + 0x4C8), &mobY, 4, NULL);
            
            // 传送玩家到怪物位置
            int one = 1, zero = 0;
            WriteProcessMemory(hProcess, (LPVOID)(playerBase + 0x28F8), &mobX, 4, NULL);
            WriteProcessMemory(hProcess, (LPVOID)(playerBase + 0x28FC), &mobY, 4, NULL);
            WriteProcessMemory(hProcess, (LPVOID)(playerBase + 0x28F0), &one, 4, NULL);
            WriteProcessMemory(hProcess, (LPVOID)(playerBase + 0x2900), &zero, 4, NULL);
            
            break;  // 只跟随第一个怪物
        }
    }
    
    // 移到下一个槽
    DWORD nextOffset;
    ReadProcessMemory(hProcess, (LPCVOID)(slot - 12), &nextOffset, 4, NULL);
    if (nextOffset != 0)
        slot = nextOffset + 16;
    else
        break;
}
```

### 关键注意事项

1. **进程句柄权限**: 需要 `PROCESS_VM_READ | PROCESS_VM_WRITE`，通常需要管理员权限
2. **时序控制**: 用定时器循环执行，推荐 50-100ms 间隔
3. **怪物死亡检测**: 可检查 `mob+0x404` (死亡标志)，跳过已死亡怪物
4. **坐标有效性**: 怪物坐标是 signed int，范围通常在 -32768~32767 (来自 short 扩展)
5. **服务端校验**: 该方案仅修改客户端内存，不保证服务端接受此位置。部分私服可能校验客户端发包是否与内存一致
6. **坐标未更新问题**: mob+0x4C4/4C8 在怪物入场时由 short 扩展为 int，部分怪物可能在移动时不同步更新此值。如果发现怪物坐标静止不动，需要改用 CPhysical 子对象 (`mob+0x178`) 中的解密坐标
