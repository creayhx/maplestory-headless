# 怪物出生时渲染机制 - 完整逆向分析

## 1. 入场流程总览

```
服务端发送 OnMobEnterField 包
        ↓
CMobPool::OnMobEnterField (0x6A6C08)
        │
        ├── Decode4 → 怪物ID
        ├── Decode1 → 召唤类型
        ├── Decode4 → 模板ID
        │
        ├── 已有怪物实例?
        │    ├─ 是 → CRC更新 + CMob__DecodeEnterFieldData()
        │    └─ 否 → CMobTemplate::GetMobTemplate()
        │             → sub_6907A7() 分配1248字节对象
        │             → sub_6907E3() 初始化字段
        │             → sub_690E09() 坐标/属性/渲染初始化
        │
        └── sub_6A03B4() 设置引用 + get_update_time()
```

---

## 2. 怪物对象分配 (sub_6907A7)

**地址**: `0x6907A7`

```c
int sub_6907A7(int a1) {
    // 分配1248字节的怪物对象
    void* v1 = ZAllocEx::Alloc(a1, 1248);
    
    if (v1) {
        return sub_6907E3(v1);  // 初始化对象
    }
    return 0;
}
```

**关键点**:
- 怪物对象大小: **1248字节**
- 使用 `ZAllocEx::Alloc` 分配内存
- 分配后立即调用初始化函数

## 4. 入场包结构处理 (sub_690E09)

**地址**: `0x690E09`

### 4.1 包解析顺序

```
sub_690E09 入场包处理:
  │
  ├── Decode4 → 怪物ID → mob+0x174
  ├── Decode2 → 初始X坐标 → mob+0x4CC / mob+0x4C4
  ├── Decode2 → 初始Y坐标 → mob+0x4D0 / mob+0x4C8
  ├── Decode1 → CRC动作值 → ZtlSecureTear → mob+0x394/0x39C
  ├── Decode2 → Foothold X
  ├── Decode2 → CY/高度
  ├── Decode1 → 入场行为类型 → [ebp-24h]
  │   ├── -4(0xFC) → 特殊处理1 (boss召唤?)
  │   ├── -3(0xFD) → 特殊处理2 (链接怪物?)
  │   ├── -2(0xFE) → 特殊处理3 (普通入场动画)
  │   ├── -1(0xFF) → 特殊处理4 (直接出现)
  │   └── >=0 → 普通入场
  ├── Decode1 → 初始动作状态 → mob+0x390
  ├── Decode4 → 入场类型/召唤类型 → [ebp-30h]
  └── DecodeString → 怪物名称 (条件性)
```

## 9. 入场动画机制总结

### 9.1 普通怪物入场

1. **无特殊入场动画**: 普通怪物直接出现，没有生成动画
2. **生成效果定时器**: `mob+0x400` 设置为 `当前时间 + 800ms`，用于控制入场后的过渡效果
3. **透明度**: 初始为255（完全不透明）

### 9.2 特殊入场类型

| 类型 | 值 | 行为 |
|------|-----|------|
| -4 | 0xFC | Boss召唤/特殊入场，可能有震动效果 |
| -3 | 0xFD | 链接怪物，与其他怪物关联 |
| -2 | 0xFE | 普通入场动画，800ms过渡 |
| -1 | 0xFF | 直接出现，无动画 |
| >=0 | - | 普通入场，根据类型可能有不同效果 |

### 9.3 渲染对象创建流程

1. 创建 `IWzVector2D` COM对象 (位置向量)
2. 设置渲染层
3. 设置颜色 (默认白色)
4. 根据入场类型设置渲染属性 (alpha, blend等)
5. 播放入场音效 (如果有标志)

## 12. 怪物渲染系统详解

### 12.1 渲染相关字段

| 偏移 | 类型 | 含义 | 引用位置 |
|------|------|------|----------|
| `mob+0x118` | ptr | **渲染层指针** (IWzVector2D) | sub_695DEE |
| `mob+0x120` | ptr | IWzVector2D COM对象指针 | sub_690E09 |
| `mob+0x280` | ptr | **渲染对象指针** (用于vtable调用) | sub_695DEE |
| `mob+0x284` | ptr | 渲染对象备用指针 | sub_695DEE |
| `mob+0x390` | byte | **Alpha/透明度** (255=不透明, 0=完全透明) | sub_6907E3 |
| `mob+0x464` | ptr | 渲染属性对象 | sub_690E09 |
| `mob+0x48C` | ptr | IWzVector2D指针 (v5+1140 in decompile) | sub_695DEE |

### 12.2 怪物更新函数 (sub_695DEE)

**地址**: `0x695DEE`

这是怪物的核心更新函数，每帧调用，处理：
- 攻击状态更新
- 伤害显示
- 特效队列遍历
- AI行为
- **渲染更新** (关键)

#### 渲染调用点 (0x696CE2 - 0x696D16)

```asm
; 怪物渲染调用 - 每帧执行
0x696CE2: mov eax, [ebx+118h]       ; eax = mob+0x118 (渲染层指针)
0x696CE8: mov edx, [eax]            ; edx = vtable指针
0x696CEA: sub esp, 10h              ; 准备参数空间
0x696CED: mov edi, esp
0x696CEF: xor ecx, ecx              ; ecx = 0
0x696CF1: push ecx                  ; 参数12 = 0
0x696CF2: push ecx                  ; 参数11 = 0
0x696CF3: push ecx                  ; 参数10 = 0
0x696CF4: push ecx                  ; 参数9 = 0
0x696CF5: lea esi, [ebp-44h]        ; 准备源数据
0x696CF8: movsd                      ; 复制4字节
0x696CF9: push ecx                  ; 参数8 = 0
0x696CFA: push ecx                  ; 参数7 = 0
0x696CFB: movsd                      ; 复制4字节
0x696CFC: lea ecx, [ebx+4C8h]       ; ecx = mob+0x4C8 (Y坐标备份)
0x696D02: push ecx                  ; 参数6 = Y坐标
0x696D03: movsd                      ; 复制4字节
0x696D04: lea ecx, [ebx+4C4h]       ; ecx = mob+0x4C4 (X坐标备份)
0x696D0A: push ecx                  ; 参数5 = X坐标
0x696D0B: push eax                  ; 参数4 = 渲染层指针
0x696D0C: mov [ebp-24h], eax        ; 保存指针
0x696D0F: movsd                      ; 复制4字节
0x696D10: call dword ptr [edx+8Ch]  ; ★★★ 调用vtable[35] (偏移0x8C) ★★★
0x696D16: test eax, eax             ; 检查返回值
```

**关键发现**: `0x696D10` 的 `call dword ptr [edx+8Ch]` 是怪物渲染的核心调用，通过vtable[35]（偏移0x8C）执行实际的精灵绘制。

### 12.3 渲染层指针详解

#### mob+0x118 (渲染层)


### 12.4 特效队列系统

**地址**: `0x6969F9` (循环入口)

```
特效队列遍历循环:
  │
  ├── mov eax, [ebx+458h]     ; 读取特效链表头 (mob+0x458)
  ├── cmp eax, edi             ; 判空 (edi=0)
  ├── jz 0x696B47              ; 空则跳过整个循环
  │
  └── [循环体]
       ├── 检查时间戳是否到期
       ├── 调用 sub_697A2D 创建视觉特效
       ├── 播放音效 (如果有标志)
       └── 从链表移除已处理条目
```

**特效条目结构** (每个约0x1C字节):
```
+0x00   时间戳
+0x04   效果类型ID
+0x08   数据
+0x0C   声音标志
+0x10   COM字符串指针
+0x14   附加参数
+0x18   附加参数
```

### 12.5 物理/动画更新入口 (sub_9BCA34)

**地址**: `0x9BCA34`

```c
// 怪物每帧物理+动画更新的核心入口
int sub_9BCA34(void *this, int a2, int a3) {
    // vtable[12] 检查是否需要更新
    if ((*(*this + 48))(this)) {
        // vtable[13] 执行物理+动画更新 (参数0x1E=30帧)
        return (*(*this + 52))(this, 30, a2, a3);
    }
    return 0;
}
```

**冻结补丁**: `0x9BCA3E` 的 `74` → `EB` (JE→JMP)，怪物完全不动。

## 13. 隐藏怪物但保留存在的实现方案

### 13.1 方案对比

| 方案 | 修改点 | 优点 | 缺点 | 推荐度 |
|------|--------|------|------|:------:|
| **A: 设置Alpha=0** | mob+0x390 | 简单，渲染系统仍处理 | 仍有CPU开销 | ⭐⭐ |
| **B: 跳过渲染调用** | 0x696D10 | 完全跳过绘制 | 需要判断怪物ID | ⭐⭐⭐ |

### 13.2 方案A: 设置Alpha=0 (最简单)

**原理**: 将怪物透明度设为0，怪物完全透明但渲染系统仍处理。

**Hook点**: `sub_690E09` 中 `mob+0x390` 的设置

```
地址: 0x690ED7
原指令: mov [ebx+228h], eax    ; mob+0x390 = 从包中读取的值
修改为: mov byte [ebx+228h], 0  ; 强制Alpha=0
```

**Patch**:

| 地址 | 原指令 | 改为 | 说明 |
|------|--------|------|------|
| `0x690ED7` | `89 83 28 02 00 00` (mov [ebx+228h], eax) | `C6 83 28 02 00 00 00` (mov byte [ebx+228h], 0) | 7字节 |

**效果**:
- ✅ 怪物完全透明
- ✅ 所有逻辑正常运行 (AI、攻击、碰撞)
- ✅ HP条、伤害数字仍显示
- ⚠️ 渲染系统仍处理怪物 (CPU开销未减少)

### 13.3 方案B: 跳过渲染调用 (推荐)

**原理**: 在怪物渲染调用点，跳过绘制但保留逻辑。

**Hook点**: `0x696D10` 的 `call dword ptr [edx+8Ch]`

```
地址: 0x696D10
原指令: FF 52 8C    call dword ptr [edx+8Ch]
修改为: 90 90 90     NOP (3字节)
```

**效果**:
- ✅ 完全跳过怪物精灵绘制
- ✅ 所有逻辑正常运行
- ✅ 减少渲染CPU开销
- ⚠️ 需要条件判断 (只隐藏特定怪物)

### 13.4 方案C: 条件隐藏 (高级)

**原理**: 根据怪物ID或模板决定是否隐藏。

**Hook点**: `0x696CE2` (渲染调用前)

```asm
; 原始代码
0x696CE2: mov eax, [ebx+118h]

; 修改后 (伪代码)
0x696CE2: push eax
0x696CE3: mov eax, [ebx+174h]    ; 读取怪物ID
0x696CE9: cmp eax, 目标怪物ID    ; 比较
0x696CEC: pop eax
0x696CED: je skip_render          ; 相等则跳过渲染
0x696CEF: mov eax, [ebx+118h]    ; 原始指令
0x696CF5: ...                     ; 继续渲染
skip_render:
0x696CF5: jmp 0x696D28           ; 跳过渲染调用
```

### 13.5 方案D: 隐藏渲染层 (最彻底)

**原理**: 将渲染层指针置空，跳过整个渲染流程。

**Hook点**: `0x696CE2`

```asm
; 原始代码
0x696CE2: mov eax, [ebx+118h]    ; eax = 渲染层指针

; 修改后
0x696CE2: xor eax, eax           ; eax = 0 (空指针)
0x696CE4: jmp 0x696D16           ; 跳过渲染调用
0x696CE9: nop x5                 ; 填充
```

**效果**:
- ✅ 完全跳过渲染
- ✅ 渲染层指针为空，后续检查会跳过
- ⚠️ 需要验证不会崩溃

## 14. 完整Hook方案

### 14.1 ✅ 隐藏所有怪物（简洁版：patch渲染指针读取，仅8字节）

**与怪物特效同一思路**：特效系统patch的是 `0x6969F9` 处读取 `mob+0x458` 的指令。渲染系统同理——patch `0x696CE2` 处读取 `mob+0x118` 的指令。

只改 **两个相邻指令，共8字节**，无需code cave：

```asm
[ENABLE]
// 将渲染层指针设为0 + 跳过vtable解引用
// 效果: 所有怪物不绘制, AI/碰撞/攻击全部正常
0x696CE2:
  db 31 C0 90 90 90 90    // xor eax,eax + nop x4

0x696CE8:
  db EB 2C                 // jmp 0x696D16 (跳过渲染调用)

[DISABLE]
0x696CE2:
  db 8B 83 18 01 00 00     // mov eax, [ebx+118h]

0x696CE8:
  db 8B 10                 // mov edx, [eax]
```

**效果**：
- ✅ 所有怪物立即消失
- ✅ AI/碰撞/攻击正常  
- ✅ 死亡流程正常
- ⚠️ 不节省CPU（但仍走函数调用，只是跳过绘制）

### 14.2 隐藏特定怪物 (按ID)

需要更复杂的Hook，建议使用CE脚本：

```asm
[ENABLE]
alloc(newmem, 2048, 0x696CE2)
alloc(monsterID, 4)

newmem:
  push eax
  mov eax, [ebx+174h]        ; 读取怪物ID
  cmp eax, [monsterID]       ; 与目标ID比较
  pop eax
  je skip_render
  mov eax, [ebx+118h]        ; 原始指令
  jmp 0x696CE8
  
skip_render:
  xor eax, eax
  jmp 0x696D16
  
monsterID:
  dd 0                        ; 在此填入要隐藏的怪物ID

0x696CE2:
  jmp newmem
  nop

[DISABLE]
0x696CE2:
  mov eax, [ebx+118h]
  
dealloc(newmem)
dealloc(monsterID)
```

## 16. 补遗：IDA深度分析与关键修正

> 以下内容基于连接到IDA Pro后的实时反编译结果，对原文档中的理解进行了重要修正和补充。

### 16.1 原文档函数误识别修正

| 函数 | 原文档描述 | IDA分析实际功能 |
|------|-----------|----------------|
| `sub_40318F` | 渲染对象创建 | **VARIANTARG复制** (`VariantInit` + `ZComAPI::ZComVariantCopy`)，纯COM参数准备 |
| `sub_4031B5` | 渲染属性设置 | **VARIANT类型标签设置器**：a3=3→VT_INT, a3=10→VT_BOOL, a3=11→VT_ERROR |
| `sub_414899` | 渲染属性指针获取 | **COM QueryInterface包装**：调用 `this->vtable[57](this, &result)` 获取子接口指针 |
| `sub_411FE1` | 渲染层设置 | **引用计数智能指针包装器**：`*this=13` + `*(this+2)=ptr` + 条件性AddRef |
| `sub_414B5F` | — | **简单解引用**：`return *this`（仅3字节，1条指令） |

**影响**：原文档第5节（渲染对象创建）中描述的"创建IWzVector2D COM对象"和"设置渲染层"实际是：
- **真正的渲染对象创建**由 `sub_9C3D58` 和 `sub_6A34E4` 完成
- `sub_40318F` / `sub_4031B5` 只是COM方法调用的参数准备，每个"创建"调用实际上是在准备VARIANT参数给后续的COM方法

### 16.2 真正的渲染对象创建链

#### `sub_9C3D58` (0x9C3D58) — 渲染控制器分配

```
sub_9C3D58() → 分配1256字节渲染控制对象
   ↓
sub_9C3B83() → 初始化对象
   ↓
返回指针 → 存入 [ebp-1Ch] → 通过 sub_6A34E4 写入 mob+0x118
```

```c
// 伪代码
int sub_9C3D58() {
    v1 = ZAllocEx::Alloc(1256);       // 分配1256字节
    if (v1)
        return sub_9C3B83(v1);        // 初始化
    return 0;
}
```

#### `sub_9C3DAD` (0x9C3DAD) — 位置控制器初始化

```c
int sub_9C3DAD(void *this, int a2, int a3, int a4) {
    CVecCtrl::Init(a2);               // 位置控制器初始化
    *(this + 142) = a3;               // 设置字段
    *(this + 143) = a4;               // 设置字段
    return a4;
}
```

#### `sub_6A34E4` (0x6A34E4) — COM指针赋值（仿QueryInterface）

```
输入：this = 目标智能指针, a2 = 源COM对象
   ↓
if (*a2 非空) {
    调用 a2->vtable[3](a2, IID, &result)  → QueryInterface获取正确接口
    释放旧指针 (*this->vtable[2])(*this)
    *this = result  ← 赋值新指针
} else {
    释放旧指针，清空
}
```

**关键发现**：`mob+0x118` 和 `mob+0x11C` 分别用 `sub_9C3D58` 分配和 `sub_6A34E4` 赋值，说明怪物在入场时分配了**两个不同的渲染控制对象**。

### 16.3 渲染层vtable调用完整映射

通过IDA分析 `sub_690E09` 中所有对渲染层对象的COM调用：

| 地址 | vtable偏移 | 索引 | 参数 | 用途 |
|------|-----------|:----:|------|------|
| `0x6910BF` | `[eax+4]` | **1** | 7个EDI(0) | 首次初始化渲染层 |
| `0x691198` | `[ecx+64h]` | **25** | COLORREF, position等 | 设置初始位置和渲染参数 |
| `0x6911EC` | `[ecx+0E0h]` | **56** | `byte_FFFFFF` (白色) | **设置颜色**(白色=0xFFFFFF) |
| `0x69150E` | `[ecx+90h]` | **36** | alpha=0xFF, blend=0 | 类型-1/-3/-4的渲染属性 |
| `0x69160D` | `[ecx+90h]` | **36** | alpha=0xFF, blend=0 | 同上（链接怪物路径） |
| `0x691711` | `[edx+90h]` | **36** | alpha=0xFF, blend=0xFF | 类型-2的渲染属性(blend=255) |
| `0x691848` | `[ecx+90h]` | **36** | alpha=0xFF, blend=0 | 类型-4 Boss路径 |

#### 每帧渲染调用（怪物更新函数）

| 地址 | vtable偏移 | 索引 | 用途 |
|------|-----------|:----:|------|
| `0x696D10` | `[edx+8Ch]` | **35** | **每帧核心精灵绘制**(mob+0x118渲染层) |

**解读**：
- vtable[35] (0x8C) 和 vtable[36] (0x90) 功能相近但不同
- vtable[36] 在入场时调用，**设置**渲染属性（alpha + blend参数）
- vtable[35] 在每帧更新时调用，**执行**实际的精灵绘制
- vtable[56] (0xE0) 设置颜色
- vtable[25] (0x64) 设置位置

### 16.4 渲染调用的完整参数布局

`0x696CE2~0x696D10` 的渲染调用参数栈布局：
