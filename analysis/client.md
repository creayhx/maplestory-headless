# client — 配套桌面客户端

与 `analysis/` 笔记配套的桌面客户端项目（仓库 `mp-multi-client`，Rust 后端在 `src-tauri/`）。

**定位**：多开 + 内存功能 + 脚本自动化的一体化外壳。
`analysis/` 里的地址与结论，最终落地成这个客户端里可勾选的功能。

> 本文只讲**架构与模块职责**，不涉及内部实现细节。

---

## 技术栈

| 层 | 选型 |
|---|---|
| 外壳 | **Tauri 1**（窗口 650×500，系统托盘；`protocol-asset` / `dialog` / `http` 插件） |
| 前端 | React + TypeScript + Vite + Tailwind + Radix UI；Monaco 编辑器；zustand 状态；react-router |
| 后端 | Rust（`windows` 0.43 直接调 Win32 / DXGI / Direct3D11）+ `image` / `imageproc` 做图像处理 |

Rust 侧是一个 Cargo 工作区，包名 `mp`：

```
maple/            游戏业务层 —— 版本化的"能力"实现
client/           Win32 底层封装 —— 无业务，只做系统调用
resource-loader/  客户端 WZ 资源读取 —— 名字表与图片
src/              Tauri 应用层 —— 命令接口、脚本引擎、工具功能
```

## 分层架构

### 1. `client/` — Win32 底层

不含任何游戏知识，只提供「对任意进程做事」的原子能力。

| 模块 | 职责 |
|---|---|
| `windows` | 窗口枚举、按 PID 找窗口、取窗口 DC |
| `snapshot` | 进程快照（按名查 PID、查模块地址） |
| `mem` | 进程内存读写（拿句柄、读/写任意地址） |
| `mem_switch` | 开关型写入 |
| `mem_hook` | 代码 Hook（改写指令流） |
| `mem_group` | 成组写入（一次改多个地址） |
| `dll` | **DLL 注入**（远程线程加载）与模块基址查询 |
| `key` / `key_code` / `mouse` | 键鼠输入模拟与虚拟键码表 |
| `color` | 屏幕取色 |
| `process` | 进程生命周期 |

### 2. `maple/` — 游戏业务层（核心）

关键设计是 **Capability（能力）驱动**：前后端之间只有一个"功能实体"概念 ——
**版本模块只注册自己支持的能力；不注册 = 不支持 = 前端不显示**。
所以裁功能不用动前端，也不会出现"界面有这个按钮但点了没用"。

| 模块 | 职责 |
|---|---|
| `capability.rs` | **63 项能力标识** + `VersionCaps` 注册表 —— 整个项目的中心抽象 |
| `dispatch.rs` | 全局「版本 → 能力表」映射，按当前游戏版本分发 |
| `version.rs` | 游戏版本枚举（`V079` / `V085` / `V124`）与当前版本状态 |
| `context.rs` | `ClientContext` —— 已附着客户端的 pid / 进程句柄 / 窗口句柄 / 窗口 DC |
| `open_client.rs` | 按 PID 附着，装配出 `ClientContext` |
| `hs_bypass.rs` | **反作弊绕过与启动**：部署绕过文件、批量打补丁、广告窗/主窗口处理 |
| `handle_scan.rs` | **句柄扫描** —— 多开的基础（枚举并处置命名对象句柄） |
| `v079/` | **079 完整实现**（见下） |
| `v085/` | 085 骨架，仅登记版本 |
| `v124/` | 124 实现（能力集明显小于 079） |

`v079/` 按游戏对象切分：

```
player   人物：开关、坐标、锁型循环      mob      怪物：行为干预、跟随、吸怪注入
item     物品：速显、全屏捡取、掉落归属   buff     属性：8 项 BUFF 的加密块改写
reactor  放置物：无延迟、全图攻击        map      地图：四壁、属性、地图 ID
inventory 背包遍历                      pet      宠物拾取
game     界面：隐藏伤害数字 / 背景        queries  只读查询
```

### 3. `resource-loader/` — WZ 资源

从客户端 `data/` 读名字与图片，复用 `wz_reader`：
`string` · `map` · `mob` · `npc` · `reactor` · `image_parser` · `utils`

让功能项显示**中文名**而不是裸 id。

### 4. `src/` — Tauri 应用层

前端与后端之间的接口层，也是跨模块的编排者。共 **72 个 Tauri 命令**，按模块：

| 模块 | 命令数 | 职责 |
|---|---|---|
| `init_cmd` | 14 | 生命周期：附着/关闭客户端、版本切换、能力表下发、PID/应用列表、进程存活、文件存在 |
| `common_cmd` | 10 | 通用：光标位置/颜色、窗口显隐、截屏、匹配结果、`talk` / `portal` / `go` / `attr` |
| `tool_cmd` | 9 | **工具类：调速、分辨率、多开互斥体、启动器、补丁**（见下节） |
| `template_cmd` | 8 | 图像模板：列表、增删改、匹配、导入导出、截帧 |
| `map_cmd` | 5 | 地图：ID、墙壁、属性（读 + 写） |
| `filter_cmd` | 5 | 物品**过滤**与**监控**（开/关/取列表） |
| `hotkey_cmd` | 5 | 热键：系统热键 + 功能热键 + 脚本热键的注册/注销 |
| `config_cmd` | 4 | 配置读 / 存 / 导出 / 导入 |
| `executor_cmd` + `exec_cmd` | 3 | 脚本执行器启停与客户端关闭 |
| `cheat_cmd` | 2 | BUFF 设置、吸怪注入 |
| `press_cmd` | 2 | 按键 / 消耗品 |
| `resource_cmd` | 2 | 加载资源、加载地图 |
| `inventory_cmd` | 1 | 背包页签读取 |
| `reactor_cmd` | 1 | Reactor 计数 |
| `game_info_cmd` | 1 | 游戏信息汇总 |

其余子系统：

| 模块 | 职责 |
|---|---|
| `script/` | **脚本引擎**：`parse` → `command` → `execute` → `check` |
| `dxgi.rs` | DXGI 桌面复制截屏（给找图找色供帧） |
| `template.rs` | 图像模板匹配（模板目录 `masaka`，并行匹配 + 相似度阈值） |
| `color_search.rs` | 颜色搜索（按色值在截屏里定位） |
| `task.rs` | **命名任务注册表** —— 每个后台循环持停止标志，统一启停 |
| `lock.rs` | 锁线程 —— 按间隔**反复重写**内存，对抗客户端把值改回去 |
| `hotkey.rs` | 全局热键 |
| `clipboard.rs` | 剪贴板 |
| `exec_status.rs` | 执行状态上报（前端进度显示） |

## 工具类功能（`tool_cmd`）

这一组不属于"游戏能力"，而是**运行环境层面的工具** —— 面向"把游戏跑起来并调好环境"，
而不是改游戏内的状态。

### 调速（Speedhack）

| 命令 | 作用 |
|---|---|
| `mount_speedhack` | 部署调速模块到客户端目录并注入目标进程（模块以 `ddraw.dll` 的名义加载） |
| `read_speedhack_config` / `write_speedhack_config` | 读写 `speed.json`（倍率等参数） |

注入走经典的远程线程路径，且**先检查目标模块是否已加载**，避免重复注入。
游戏能力侧另有一个 `Speek`（调速）开关可与之联动。

### 分辨率

| 命令 | 作用 |
|---|---|
| `set_resolution` | 切换**屏幕**分辨率与刷新率 |
| `set_game_internal_resolution` | 游戏**内部分辨率**补丁（当前在源码中注释停用，保留接口） |

屏幕分辨率与游戏内分辨率是两件事：前者改显示器模式，后者改客户端渲染尺寸。
后者与 `analysis/游戏UI尺寸.md` 里那批控件坐标常量是同一套东西。

### 多开

| 命令 | 作用 |
|---|---|
| `check_mutexes` | 探测系统里是否已存在客户端的互斥体 |
| `remove_mutex` | 遍历**所有** `MapleStory.exe` 实例，处置其互斥体句柄以解除单实例限制 |

底层依赖 `handle_scan`（枚举进程句柄 → 比对名字 → 处置）。这正是
`analysis/客户端多开.md` 分析的那套机制的产品化。

### 启动器与补丁

| 命令 | 作用 |
|---|---|
| `start_game` | 创建进程 + 部署绕过文件 + 打入初始补丁；随后**后台轮询**窗口：发现广告窗就先补丁再关闭，等主窗口出现后向前端发 `game-ready` 事件（不阻塞界面） |
| `patch_game` | 对**已在运行**的进程补丁 |

## 功能重点

### 能力注册的几种形态

| 形态 | 含义 |
|---|---|
| `flag` | **开关型** —— 写一次即生效 |
| `lock` | **锁型循环** —— 按间隔反复重写（10ms / 50ms / 300ms） |
| `query` | **只读查询** —— 读取并回传 |
| `write` | **复合写** —— 一次改多个地址 |
| `pos` | **传送/交互** —— 写坐标类操作 |
| `inject` / `action` | **注入与复位** —— 需成对清理 |
| `name` | 需按名查的能力 |
| `declared` | **声明但由应用层实现** —— 页面级（背包、筛选、监控、启动器） |

### 079 的功能面

| 类别 | 内容 |
|---|---|
| **人物** | 攻击无延迟 · 停止呼吸 · 攻击不停 · 无敌 · 游泳 · 跨图移动 · 调速 · 无技能准备特效 · 无技能特效 |
| **怪物** | 变笨 · 停止 · 加速 · 去无敌 · 秒消失 · 快速死亡 · 无受击特效 |
| **物品** | 物品速显 · 掉落到脚下 · 全屏捡取 · 拾取坐标同步 |
| **界面** | 隐藏伤害数字 · 隐藏背景 · 宠物拾取 |
| **放置物** | Reactor 无延迟 · 全图攻击 |
| **BUFF** | 攻击 / 魔攻 / 武器加速 / 移速 / 防御 / 暴击 / 祝福 / 稳如泰山 |
| **吸怪** | 注入拉怪 + 复位 |
| **查询** | 地图墙壁 / 地图属性 / 地图 ID / 游戏信息 / 人物名 / 人物数 / 怪物数 / Reactor 数 / 远程 XY / HP 条 / MP 条 / 宠物 HP |
| **传送** | 瞬移 / 过传送门 / 对话跳转 |
| **锁型循环** | 快速攻击(10ms) · 停止呼吸(50ms) · 攻击不停(300ms) · 伤害上限(100ms) · 怪物跟随(100ms) |
| **页面级** | 按键 · 消耗品 · 过滤 · 监控 · 背包 · 启动器 |

> v124 是同一套抽象的另一个版本实现，能力集小得多 —— 这正是"能力注册表"的价值：
> **版本差异被收进各自的 `capabilities()`，上层与前端都不用改**。

### 脚本引擎

一套面向"找图找色 + 按键 + 移动"的自动化脚本，指令集（16 条）：

`origin`（起点）· `move` / `pos`（移动）· `attack`（攻击）· `area`（区域）·
`time` / `while`（流程控制）· `waitcolor`（等色）· `waitnfind` / `wcheck`（找图校验）·
`frclick` / `fsrclick` / `fchars` / `morekey` / `fkeyup`（模拟输入）· `end`

解析与执行分离，并带独立校验与测试。

## 与 `analysis/` 笔记的关系

| `analysis/` 里是 | `client/` 里是 |
|---|---|
| 地址、结构偏移、Hook 点的**考证** | 把它们封装成 `Capability`（63 项） |
| `MapleStory079.CT`（251 条目） | 同样的功能以**勾选开关**呈现，CT 表也随包分发 |
| `冒险岛过HS+移除上限.md` 的启动流程 | `hs_bypass.rs` + `start_game` 命令 |
| `客户端多开.md` 的句柄原理 | `handle_scan.rs` + `remove_mutex` 命令 |
| `游戏UI尺寸.md` 的控件坐标 | `set_resolution` / 分辨率相关分组 |

**笔记回答"为什么能这么改"，客户端回答"怎么让人用得着"。**
