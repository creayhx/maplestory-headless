# 宠物拾取分析 — MapleStory.exe+10D7A6

## 概述

地址 `MapleStory.exe+10D7A6` 对应的是函数 **`CDropPool__GetDropByPos`**（按坐标查找掉落物）内的关键条件跳转。将此处 `75`（JNZ）改为 `EB`（JMP）可**跳过物品距离检测**，使宠物/玩家能拾取任意距离的掉落物。

---

## 地址速查

| 项 | 值 |
|---|---|
| RVA | `MapleStory.exe+10D7A6` |
| 绝对地址 | `0x50D7A6` |
| 所属函数 | `CDropPool__GetDropByPos`（`0x50D63B`–`0x50D856`） |
| 原始字节 | `75 09` |
| 修改字节 | `EB 09` |
| 修改效果 | `jnz loc_50D7B1` → `jmp loc_50D7B1`（条件跳转→无条件跳转） |

### 字节验证

```

```

    ├── CDropPool__PickupDrop (0x50D440)
    │     ├── 捡取边界框构造 (bbox: [x-25, y-50, x+25, y+10])
    │     ├── 落地保护检测（掉落 > 3秒？）
    │     ├── call dword_BE1734 (bbox, dropX, dropY)  ← 距离检测①
    │     ├── test eax,eax / jnz → loc_50D5E3         ← 0x50D5B9
    │     └── → SendPickupRequest (sub_A126C5)
    │
    └── CDropPool__GetDropByPos (0x50D63B)
          ├── 捡取边界框构造 (bbox: [x-25, y-50, x+25, y+10])
          ├── call dword_BE1734 (bbox, dropX, dropY)  ← 距离检测② ★
          ├── test eax,eax / jnz → loc_50D7B1         ← 0x50D7A6 ★ PATCH HERE
          │     ├── → 检查物品归属权
          │     ├── → 检查物品主人是否允许其他人捡取
          │     └── → SendPickupRequest (sub_70F4C0)

**有两个函数的调用流程中都包含 `dword_BE1734` 距离检测**：

| 函数 | 检测点地址 | 指令 | 跳跃目标 |
|------|-----------|------|---------|
| `CDropPool__PickupDrop` | `0x50D5B9` | `75 26`→`EB 28` | 跳过检测，直接发包捡取 |
| `CDropPool__GetDropByPos` | **`0x50D7A6`** | `75 09`→`EB 09` | 跳过检测，继续拾取流程 |

## `dword_BE1734` 详解

是一个**运行时动态解析的函数指针**（位于 `0x00BE1734`），IDA 静态数据库中为 `0x00000000`。

### 签名

```c
// __stdcall
int __stdcall PtInRect(LPRECT lpBoundingBox, int dropX, int dropY);
```

### 参数

| 参数 | 来源 | 说明 |
|------|------|------|
| `lpBoundingBox` | `[ebp-38h]` | 捡取边界框 `RECT{x1,y1,x2,y2}` |
| `dropX` | `TSecType_long::GetData(drop+0x74)` | 掉落物加密X坐标 |
| `dropY` | `TSecType_long::GetData(drop+0x68)` | 掉落物加密Y坐标 |

### 返回值

| 值 | 含义 |
|----|------|
| 非零 | 物品在捡取范围内 → **允许拾取** |
| 0 | 物品超出捡取范围 → **跳过** |

## 判断逻辑拆解

### 距离检测前 —— 物品筛选条件

```c
// CDropPool__GetDropByPos 中的完整筛选链
for each drop in droppool:
{
    // 1. 物品必须有效
    if (drop->field_88 == NULL) continue;

    // 2. 玩家必须在线
    if (dword_BDD490 == NULL) continue;

    // 3. 宠物/召唤兽必须在场
    if (CUser->petInfo->field_04 == NULL) continue;

    // 4. 检查物品是否属于"当前地图人物可见"
    if (sub_70F58E(player) 不通过) continue;

    // 5. 如果是他人物品，检查是否"自由拾取"模式
    if (drop->ownerType == 0 && drop->ownerId != player->field_2084) continue;
    if (drop->ownerType == 1 && drop->ownerId != player->field_2E04) continue;

    // 6. 物品必须为可见状态 (drop->field_1D != 0)
    // 7. 物品类型必须为掉落物 (drop->field_48 == 3)
    // 8. 落地保护：如果owner是玩家，需落地 > 15000ms
    // 9. 落地保护：所有物品需落地 >= 3000ms

    // ★ 10. 距离检测 ★
    if (PtInRect(bbox, dropX, dropY))   // ← 0x50D7A6 这个跳转
        goto PICKUP_PATH;               // JNZ → 跳入拾取路径
    else
        continue;                       // 跳过
}
```

### Patch 效果

将 `0x50D7A6` 的 `75`（JNZ）改为 `EB`（JMP）后，**条件 10（距离检测）永不失败** —— 只要前面的 9 个条件全部满足，物品必定进入拾取路径。

> ⚠️ 注意：**不修改前面的筛选条件**。这意味着：
> - 他人的私人掉落物仍然无法捡取（条件 5）
> - 隐身/不可见的物品无法捡取（条件 6）
> - 非掉落物类型的无法捡取（条件 7）
> - 刚掉落的物品仍需等待 3 秒落地保护（条件 9）
>
> 它只跳过了"**玩家与物品之间的距离检测**"。

## 与 `CDropPool__PickupDrop` (0x50D440) 的区别

| 对比项 | `CDropPool__PickupDrop` (0x50D440) | `CDropPool__GetDropByPos` (0x50D63B) |
|--------|-----------------------------------|--------------------------------------|
| 触发方式 | **主动拾取键**（Z 键/鼠标点击） | **宠物自动拾取** / 鼠标点击范围捡取 |
| 功能 | 从掉落池中遍历 + 距离检测 + 发包 | 根据指定坐标在掉落池中搜索匹配的掉落物 |
| 距离检测地址 | `0x50D5B9` | `0x50D7A6` |
| 已有文档 | 物品捡取距离检测.md | **本文档** |
| 已有方案 | 全屏捡取方案二（跳过距离检测） | N/A（这是宠物拾取路径） |

因此，用户问的 `MapleStory.exe+10D7A6` 是**宠物拾取**的距离检测点，与已有的 `0x50D5B9`（主动按键拾取）不同。
