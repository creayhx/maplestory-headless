# 物品消失流程分析

## 概述

物品（Drop）从地图上消失由 `CDropPool` 类处理，包含服务端通知和本地更新两条路径。

## 关键类：CDropPool

函数地址表：

| 函数 | 地址 | 大小 |
|------|------|------|
| CDropPool::OnPacket | 0x50E6CF | 0x25 |
| CDropPool::OnDropEnterField | 0x50E6F4 | 0xB16 |
| CDropPool::OnDropLeaveField | 0x50F385 | 0x610 |

## 服务端→客户端通知

```
CField::OnPacket(0x54112E)
└── opcode 272(0x110) → CDropPool::OnPacket(0x50E6CF)
    ├── 272 → OnDropEnterField  // 物品出现在地图
    └── 273 → OnDropLeaveField  // 物品从地图消失
```

### OnDropLeaveField 消失类型

函数入口读取的第一个 byte (`v2 = CInpacket::Decode1`) 为消失类型：

| v2 | 含义 | 行为 |
|----|------|------|
| **0** | **玩家拾取** | 完整的拾取处理逻辑：动画、音效、物品入包、UI 更新 |
| **2** | 被其他人捡走 | 显示 "Someone else has already picked up the item" |
| **3** | 特定消失 | 类似处理 |
| **4** | **超时消失** | 读取过期时间并设置标记 `obj->field_72 = 4`，立即返回 |
| **5** | 被其他人捡走(变体) | 显示提示 + 额外读取 byte |

类型 0 (玩家拾取) 的代码路径（`0x50F43C`）包含：
- 获取物品图标和名称
- 调用动画显示效果
- 播放拾取音效
- 更新背包 UI
- 释放 COM 资源

## 物品更新循环：sub_50D9F3 (0x50D9F3)

掉落的本地状态更新函数（每帧调用），遍历所有活跃掉落物。

### 状态机

| State (obj+72) | 含义 | 行为 |
|----------------|------|------|
| 0 | 正常等待 | 检查 `current_time > expire_time` → 超时则设 State=1 |
| 1 | 已过期 | 开始消失动画，obj+76 递增 |
| 2 | 消失中 | 透明度/位置插值计算 |
| 3 | 完全移除 | 移除动画结束后，调用 `sub_50E4A3` 从池中删除 |
| 4 | 服务端标记过期 | 由 LeaveField type=4 设置 |

### 超时消失路径

```
0x50E222: current_time - obj->expire_time
  如果 > 0 → 设 State=1 (0x50E22D)
  → 播放淡出动画
  → obj+76 += 30 (每帧)
  → 检查 obj+76 >= obj+80 → 设 State=2 → 继续缩小
  → obj+76 >= obj+80 → 设 State=3 → 调用 sub_50E4A3 移除
```

## 拾取按键流程

### 按键处理链

```
sub_9535F1 (0x9535F1)  — 按键按下/释放处理器
  └── a3 == 0 (按键释放)
      └── a2 >= 4 && a2 < 0x16
          └── v20[a2] == 3  (动作类型=3 即拾取)
              └── sub_50D440 (0x50D440)  — 遍历掉落物并发起拾取
```

动作类型 `v20[a2]` 对应关系：
| 类型 | 含义 | 处理函数 |
|------|------|----------|
| 1 | NPC 对话 | sub_954F0F |
| 2 | 坐下/起身 | sub_95308C / sub_952F1F |
| **3** | **拾取** | **sub_50D440** |
| 4-9 | 快捷栏动作 | sub_955C96 |

注意：sub_955C96 中 action 0 分支（`v12 = *(v10 + 1) - 50` 递减后为 0 的情况）也会调用 sub_50D440，这是另一种触发拾取的路径（可能用于自动化/宠物拾取）。

### sub_50D440 (0x50D440) — 核心拾取函数

**作用**：遍历地面上所有掉落物，检查距离，对符合条件的发送拾取包。

```
sub_50D440(this, player_pos)
  // 定义拾取范围边界框
  bbox.x1 = player_x - 25
  bbox.y1 = player_y - 50
  bbox.x2 = player_x + 25
  bbox.y2 = player_y + 10

  // 遍历全部掉落物
  for each drop in CDropPool:
    跳过条件：
      - 是装备且 sub_6097AA 检查失败
      - 时间/拥有者条件不满足：
        - 非无主且非自己掉落 && 非组队掉落
        - 或 掉落存在 > 15 秒 && 没有来源怪物
      - drop->state != 3 (不是可拾取状态)
      - 落地 < 3 秒 (anti-pickup delay)

    距离检测：
      if dword_BE1734(bbox, drop_x, drop_y):
        // 距离合法，发送拾取包
        sub_A126C5(..., drop_id, ...)
        return
```

### sub_A126C5 (0xA126C5) — 发送拾取请求包

```
创建 COutPacket(opcode = 198)
  Encode1(field_player_id)    // 从 sub_4376F2() + 300
  Encode4(get_update_time())  // 当前时间戳
  Encode2(player_x)           // 玩家 X 坐标
  Encode2(player_y)           // 玩家 Y 坐标
  Encode4(drop_id)            // 掉落物 ID
  Encode4(item_id)            // 物品 ID
CClientSocket::SendPacket()
```

**拾取包 opcode = 198 (0xC6)** 是客户端→服务端的拾取请求。

发送后设置标记：`*(v8 + 8328) = 1`，`*(v8 + 8332) = get_update_time()`，`*(v8 + 13724) = 1`

## 全屏捡取可行性分析

### 当前拾取范围

```
X 轴: player_x - 25  ~  player_x + 25   (约 50 像素宽)
Y 轴: player_y - 50  ~  player_y + 10   (约 60 像素高)
```

这是一个非常小的范围，就是角色脚下的区域。

### 方案一：修改拾取范围边界值 ✅ 最简单

在 `sub_50D440` 开头，边界框的赋值指令处修改：

| 位置 | 原指令 | 修改为 |
|------|--------|--------|
| `0x50D44E` | `v9 - 25` (x1) | `v9 - 10000` |
| `0x50D453` | `v10 - 50` (y1) | `v10 - 10000` |
| `0x50D458` | `v9 + 25` (x2) | `v9 + 10000` |
| `0x50D45D` | `v10 + 10` (y2) | `v10 + 10000` |

**优点**：
- 改造成本极低，改 4 个立即数即可
- 不需要理解复杂的逻辑

**缺点**：
- **服务端可能仍有距离验证**，发包过去会被拒绝
- 如果服务端信任客户端坐标，则有效

### 方案二：NOP 掉距离检测

将 `dword_BE1734` 调用及条件跳转改为无条件跳转：

```
0x50D4ED: call dword_BE1734  →  mov eax, 1 (或 NOP + mov al,1)
0x50D4F3: jz ...              →  jmp ... (总是执行拾取)
```

### 方案三：遍历所有物品发包（CE 脚本）

如果服务端每次只允许捡起一个物品，需要写 CE 脚本/注入 dll：
1. 遍历 CDropPool 中所有 drop
2. 对每个 drop 调用 `sub_A126C5` 发包
3. 配合防封延迟

### 方案选择建议

| 场景 | 推荐方案 |
|------|----------|
| 服务端不验证距离 | 方案一（改边界值） |
| 服务端验证距离但没冷却 | 方案一即可 |
| 服务端验证距离且有冷却 | 需要服务端 mod |
| 一次捡所有物品 | 方案三（遍历发包） |

### 注意

方案一和方案二基于 `sub_50D440` 的拾取按键路径。此外 `sub_955C96` 中 action 0 分支也调用 `sub_50D440`，同样的 patch 会同时影响两个路径。

如果仅改客户端不生效，说明距离验证在服务端，需要：
1. 使用 `sub_A126C5` 的格式手动构造更大的范围 Pickup 包
2. 或者直接改服务端逻辑（私服）

## 物品掉落结构体

基于 `OnDropEnterField` 和 `OnDropLeaveField` 中的偏移量：

| 偏移 | 大小 | 含义 |
|------|------|------|
| +28 | byte | Drop 类型（落地的第一个 byte） |
| +29 | byte | 是否为 1/2 类型 |
| +32 | dword | Drop ID |
| +36 | dword | X 坐标 |
| +40 | dword | 怪物/来源 ID |
| +44 | byte | 未知 |
| +48 | byte | 是否为装备 (0/1) |
| +52 | dword | 物品 ID |
| +56 | ptr | 图标/UI 相关 |
| +60 | ptr | 动画相关 |
| +64 | dword | 过期时间戳 (enter_time + duration) |
| +68 | dword | 过期时间戳 (LeaveField type=4 用) |
| +72 | dword | 状态标记 (0=正常, 1=过期, 2=消失中, 3=已移除, 4=过期标记) |
| +76 | dword | 消失进度计数 |
| +80 | dword | 消失进度上限 |
| +84 | dword | enter_time - 3000 |
| +88 | dword | 拥有者 Character ID |
| +96 | float | 浮动 offset |
| +104 | long | Y 坐标 (TSecType_long) |
| +116 | long | 某种数据 (TSecType_long) |
| +128 | byte[8] | 数据缓冲区 (非装备 8 字节，或从包中读取) |
| +136 | byte | 额外标志 |
