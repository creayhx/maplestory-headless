# 冒险岛 背包物品分析

## 基本信息

| 项目 | 内容 |
|------|------|
| 目标进程 | MapleStory.exe (32-bit) |
| 基址 | 0x400000 (无 ASLR) |
| 人物基址 | `dword_BD9028` (0x00BD9028 → CWvsContext) |

## 调用链

```
CWvsContext (0xBD9028)
  └── GetCharacterData (0x426F51)
      └── CWvsContext + 0x2094 → CharacterData
```

### CWvsContext::GetCharacterData (0x426F51)

**作用**：从 CWvsContext 对象中取出 CharacterData 指针并递增引用计数返回。

**调用时机**：游戏各个系统（背包/装备/技能/任务等）需要访问角色数据时都会调用此函数，**调用频率很高**，Hook 此函数可以实时获取背包数据。

```c
CWvsContext *__thiscall CWvsContext::GetCharacterData(CWvsContext *this) {
    // 从 this + 0x2094 读取 CharacterData 指针
    CharacterData *result = *(CharacterData **)((char *)this + 0x2094);
    if (result == NULL)
        return NULL;
    // 递增引用计数
    InterlockedIncrement(&result->refCount);
    return result;
}
```

### CharacterData::GetItem (0x4296B0)

**作用**：按标签和槽位获取物品指针。

**调用约定**：`ECX = CharacterData*`，栈参数依次为 `&result` (8字节结构体)、`tab` (栏位，消耗栏=2)、`slot` (槽位，1~96)。

**返回值**：通过 `result` 结构体返回，`result+4` 为 GW_ItemSlotBase* 指针（若为空表示该格无物品）。

### CharacterData 构造 (sub_467D26, 0x467D26)

CharacterData 在构造时会初始化所有背包容器：

```
CD + 0x00 ~ 0x08: 3个 Ztl 容器（用途待定）
CD + 0x2CB: 背包容器1（装备栏）      → Ztl_Multiset* (DWORD)
CD + 0x2CF: 背包容器2（消耗栏）      → Ztl_Multiset* (DWORD)
CD + 0x2D3: 背包容器3（设置栏）      → Ztl_Multiset* (DWORD)
CD + 0x2D7: 背包容器4（其他栏）      → Ztl_Multiset* (DWORD)
CD + 0x2DB: 背包容器5（现金栏）      → Ztl_Multiset* (DWORD)
```

每个容器指针为连续 DWORD，步长 4 字节。⚠️ **注意**：不是步长 8，早期分析文档有误。

## 背包容器结构 (Ztl_Multiset)

### 容器头 (12 字节)

```
偏移    大小    含义
+0x00   dword   加密的物品数量 (ZtlSecureTear 编码)
+0x04   dword   0x00000000 (高位/对齐)
+0x08   dword   加密的容量/头指针
```

### 条目区域 (+0x0C 起)

每个条目 8 字节：

```
偏移    大小    含义
+0x00   dword   GW_ItemSlotBase* 指针（指向堆上分配的物品对象）
+0x04   dword   加密的 Slot 编号
```

⚠️ **注意**：物品指针在 `entry+0x00`，Slot 编号在 `entry+0x04`。早期文档将二者顺序记反了。

遍历方式：从 `+0x0C` 开始，每 8 字节一个条目，最多 96 个条目。

### 容器基址在 CharacterData 中的偏移

| CharacterData 偏移 | 栏位 | 物品类型 |
|-------------------|------|---------|
| CD + 0x2CB | 装备栏 | Equip (虚表 0xB009D0) |
| CD + 0x2CF | 消耗栏 | Bundle (虚表 0xB00958) |
| CD + 0x2D3 | 设置栏 | Bundle (虚表 0xB00958) |
| CD + 0x2D7 | 其他栏 | Bundle (虚表 0xB00958) |
| CD + 0x2DB | 现金栏 | Cash (虚表 0xB00A50) |

每个容器指针为连续 DWORD，步长 4 字节，从 CD+0x2CB 到 CD+0x2DB 共 5 个栏位容器指针。

## GW_ItemSlot 类体系

### 虚函数表识别

| 虚表地址 | 类名 | 说明 |
|---------|------|------|
| 0x00B00958 | GW_ItemSlotBundle | 消耗/设置/其他，有数量属性 |
| 0x00B009D0 | GW_ItemSlotEquip | 装备，无数量属性，有装备属性 |
| 0x00B00A50 | GW_ItemSlotCash | 现金物品，有数量属性 |

### 通用物品结构 (GW_ItemSlotBase)

所有物品对象共有的头部结构：

```
偏移    大小    类型        含义
+0x00   dword   ptr         虚表指针
+0x04   dword   ?           未知（⚠️ 非明文堆叠数，值变化不匹配数量）
+0x08   dword   ?           填充/未知
+0x0C   4 bytes TSecType[0] 校验字节（GetData 内部与 verify_buf[5] 比对）
+0x10   4 bytes TSecType[4] 校验字节（GetData 内部与 verify_buf[6] 比对）
+0x14   dword   ptr         验证缓冲区指针（ItemID 加密数据实际存储于此）
+0x18   dword   ?           未知
+0x1C   dword   ?           未知
+0x20   dword   ?           未知
+0x24   dword   ?           未知
+0x28   4 bytes ZtlSecureTear 加密的数量（仅 Bundle/Cash）
+0x2C   4 bytes ?           扩展字段
```

⚠️ **注意**：`+0x14` 验证缓冲区指针在调用 `TSecType_long_::GetData` 前必须检查是否为 NULL。

### Bundle 物品 (GW_ItemSlotBundle)

Bundle 类型物品（消耗/设置/其他）使用上述通用结构。

关键字段：
- **+0x04**: 未知（⚠️ 非明文堆叠数，值变化不匹配数量）
- **+0x0C~0x13**: 校验字节（8字节，GetData 内部与 verify_buf 比对）
- **+0x14**: 验证缓冲区指针（解密 ItemID 前必须检查，ItemID 加密数据在此指向的缓冲区中）
- **+0x28**: 数量（ZtlSecureTear_short_ 加密，2字节）

### Equip 物品 (GW_ItemSlotEquip)

装备类型物品，增加装备属性字段（具体偏移待补充），无 +0x28 数量字段。

### Cash 物品 (GW_ItemSlotCash)

现金物品，与 Bundle 结构类似，虚表不同。

## 加密体系

### TSecType_long_ 解密 (ItemID)

⚠️ **重要修正**：早期分析认为 `item+0x0C` 处 8 字节为 `[key, encrypted]` 格式并使用 `ROL5 XOR` 解密。
反汇编 `TSecType_long_::GetData (0x429944)` 后确认真实算法如下：

**数据位置**：ItemID 加密数据**不在** `item+0x0C`，而在**验证缓冲区**（由 `item+0x14` 指向）。

**验证缓冲区格式**：

```
偏移    大小    含义
+0x00   4 bytes 加密的 ItemID 字节（4 字节，小端序）
+0x04   1 byte  running key 初始值
+0x05   1 byte  校验字节（与 item+0x0C[0] 比对）
+0x06   1 byte  校验字节（与 item+0x10[0] 比对）
+0x08   2 bytes 校验和（内部计算后比对）
```

**解密算法**：

```c
// 伪代码：从 verify_buf 解密 ItemID
BYTE verify_buf[5];  // 读取自 verify_buffer_ptr
ReadProcessMemory(hProcess, verify_buffer_ptr, verify_buf, 5, NULL);

BYTE rk = verify_buf[4];  // running key 初始值
BYTE out[4];

for (int i = 0; i < 4; i++) {
    if (rk == 0) rk += 0x2A;
    out[i] = verify_buf[i] ^ rk;
    rk += verify_buf[i] + 0x2A;  // 字节截断
}
DWORD itemId = *(DWORD*)out;  // 小端序
```

**安全要求**：调用 `TSecType_long_::GetData` 前必须检查 `item+0x14` 验证缓冲区指针不为 NULL。

### ZtlSecureTear_short_ 加密 (数量)

数量使用 2 字节 ZtlSecureTear 编码：

```
低16位(key高16位) | 高16位(key XOR 数量)
```

**解密**: `数量 = 低16位(key) XOR 高16位(key XOR 数量)`

**警告**: `ZtlSecureTear_unsigned_short_` (0x4F7856) 是**加密函数**，不可用于解密。调用它会破坏 RNG 状态 `g_rand_0` (0x00BDF028) 并返回错误结果。必须使用内联 XOR 解密。

**汇编实现**:
```asm
mov eax, [item+0x28]    ; 读取加密的数量值（32位）
mov edx, eax
and eax, 0xFFFF         ; eax = 低16位 (key)
shr edx, 16             ; edx = 高16位 (encrypted)
xor ax, dx              ; ax = 真实数量
and eax, 0xFFFF         ; 清除高位
```

### ZtlSecureTear_long_ (0x416E36) — 加密

```
输入: ECX = 明文值, EDX = 输出缓冲区(8字节)
输出: buffer[0] = key, buffer[1] = ROR4(plaintext XOR key, 5)
返回: encrypted + ROR4(key XOR 0xBAADF00D, 5)
```

> **注意**：此函数是**加密函数**，与 `TSecType_long_::GetData (0x429944)` 不同。
> 其加密算法 `ROR4(plain XOR key, 5)` 常被误认为是 ItemID 的解密算法，
> 实际上 ItemID 解密在 `0x429944`，使用 verify buffer XOR 算法（见上一节）。

### ZtlSecureFuse_long_ (0x416DE8) — 容器数量/容量解密

**注意**：此函数是 `ZtlSecureFuse_long_`，与 `TSecType_long_::GetData (0x429944)` 不同。
它使用 `ROL5 XOR` 算法解密容器头的物品数量/容量字段，**不用于 ItemID 解密**。

```
输入: a1 = [key, encrypted] (8字节), a2 = 校验和
输出: plaintext = key XOR ROL5(encrypted)
验证: encrypted + ROR4(key XOR 0xBAADF00D, 5) == a2
```

## 物品遍历与数量获取

### 核心逻辑

```
1. [0xBD9028] → CWvsContext
2. CWvsContext + 0x2094 → CharacterData
3. CharacterData + 0x2CB ~ 0x2DB → 5个背包容器指针 (每4字节一个)
4. 对每个容器:
   a. 容器 + 0x00 → 加密数量（使用 ZtlSecureFuse_long_ 解密）
   b. 容器 + 0x0C 起 → 遍历条目区，每8字节一组
      - [entry + 0x00] → GW_ItemSlotBase* 物品指针
      - [entry + 0x04] → 加密的 Slot 编号
   c. 对每个物品指针:
      - [item + 0x04] → 未知（⚠️ 非明文堆叠数）
      - [item + 0x0C] → 校验字节（GetData 用于验证，非 ItemID 加密数据）
      - [item + 0x14] → 验证缓冲区指针（ItemID 加密数据在此指向的缓冲区中）
      - [item + 0x28] → 数量（ZtlSecureTear_short_ 加密，XOR 解密，勿调用 ZtlSecureTear）
```

### 数据输出格式

```c
struct InventoryDump {
    DWORD tabCounts[5];          // 5个栏位各自的物品数量
    // 每个栏位依次排列：
    struct ItemEntry {
        DWORD itemId;    // 解密后的物品ID
        DWORD quantity;  // 解密后的数量（装备栏填0）
    } items[5][96];      // 最多5x96个物品
};
```

## Hook 方案

### Hook 点: CWvsContext::GetCharacterData (0x426F51)

**地址**: `MapleStory.exe + 0x26F51 = 0x426F51`

**原始指令 (10 bytes)**:
```asm
55         push ebp
8B EC      mov ebp, esp
51         push ecx
8B 81 94 20 00 00  mov eax, [ecx+2094]
```

**方案**: 将前 10 字节改为 `jmp CodeCave` + `nop`，在 code cave 中执行遍历逻辑后跳回原函数继续执行。

**内存方案**: 使用 CE `alloc()` 动态分配代码内存 (ScriptCode) 和数据内存 (InventoryBuffer)，不使用固定 code cave 地址。

### 数据输出地址

```
alloc(InventoryBuffer, 4096)  → 物品数据缓存区
alloc(ScriptCode, 2048)       → 汇编代码缓存
```

### InventoryBuffer 布局

```
+0x00~0x10: DWORD tabCounts[5]  — 各栏位有效物品数
+0x14:         items[]           — 每格8字节 (DWORD itemId + DWORD qty)
```
