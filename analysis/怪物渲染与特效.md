# 怪物渲染与特效系统

涵盖怪物的显示/消失动画、死亡系统、生成无敌状态、特效系统、物理/动画更新等与渲染相关的机制。

## 1. 怪物显示与消失动画

### 入场流程

```
CMobPool::OnMobEnterField (0x6A6C08):
  │
  ├── Decode4(packet) → 怪物ID
  ├── Decode1(packet) → 召唤类型
  ├── Decode4(packet) → 模板ID
  │
  ├── 已有怪物实例?
  │    ├─ 是 → CRC更新 + sub_69E42C()
  │    └─ 否 → CMobTemplate::GetMobTemplate()
  │             → sub_6907A7() 分配1248字节对象
  │             → sub_6907E3() 初始化字段
  │             → sub_690E09() 坐标/属性初始化
  │
  └── sub_6A03B4() 设置引用 + get_update_time()
```

**怪物对象初始化 (sub_6907E3):**
```
mob+0x390 = 255    (v3[228])  透明度/Alpha值(255=不透明)
mob+0x488 = 1      (v3[290])  初始动作状态
mob+0x4A0 = 31     (v3[296])
mob+0x4A8 = 100    (v3[298])
```

入场动画方面，普通怪物通常没有特殊的生成动画（直接出现），只有部分Boss/特殊怪物可能有召唤特效。

### 离场/死亡动画流程

```
CMobPool::OnMobLeaveField (0x6A6DCB):
  │
  ├── Decode4(packet) → 怪物ID
  ├── Decode1(packet) → v6 (离场类型/死亡类型)
  │
  ├── v6 != 0 ───────────────────────┐
  │    ├─ mob+0x404 = v6             │ 死亡动画路径
  │    ├─ sub_6A70EA()               │ 推入保活队列(容器+0x50)
  │    └─ → 怪物保留在队列中          │ 由更新循环控制移除时机
  │                                   │
  ├── v6 == 0 ───────────────────────┐
  │    ├─ CRC重置                     │ 直接移除路径
  │    ├─ sub_691EAE() 存活检查       │ 不播放死亡动画
  │    └─ → goto cleanup              │ 立即移除
  │
  └── 清理: sub_A0D280, sub_6A719E, sub_51B759
```

死亡后每帧处理：
```
sub_6A68F3 (CMobPool 周期性更新)
  └─ 遍历保活队列(容器+0x50)
       ├─ 调用 mob vtable 更新(含死亡动画帧推进)
       └─ 检查 mob+0x3A0 死亡计时器 (ZtlSecureFuse 加密)
            ├─ 解密值 > -1 → jg 0x6A6A90 → 跳过移除,动画继续
            └─ 解密值 <= -1 → 走移除路径 → sub_692719 触发二阶段/掉落
```

关键变量：
- `v6 = Decode1()`：从包中读取1字节的离场类型
- `mob+0x404`：存储离场类型（非0=死亡动画中，0=正常）
- `v6 == 0`：立即移除路径（无死亡动画）
- `v6 != 0`：死亡动画路径（播放动画后移除）

## 2. 死亡动画加速/跳过

### 方案对比

| 方案 | 保活队列 | 死亡动画 | 二阶段触发 | 推荐度 |
|------|---------|---------|-----------|:-----:|
| **D: 修改计时器初值** | ✅ 正常入队列 | 0秒(立即到期) | ✅ 正常触发 | ⭐⭐⭐ |
| ~~A: NOP 0x6A6E27~~ | ❌ 不入队列 | 无 | ❌ 不触发 | ❌ |
| ~~NOP 0x6A6A45~~ | ✅ 入队列 | 1帧~无 | ❌ 前置条件不满足 | ❌ |

### ✅ 方案D（推荐）：修改死亡计时器初始值为-1

**原理：** 怪物死亡时，计时器初始值通过 ZtlSecureTear 加密写入 mob+0x3A8。正常值 ≈ 21ms。将其改为 -1（0xFFFFFFFF），加密后每帧检查即触发移除。

```
sub_691F21 (死亡类型0-1处理):
  │
  ├── 死亡类型==3 → push 0x15 (21ms)        @ 0x691FB6 ← Patch 1
  │
  └── 其他类型(默认) → add ecx, 9 (随机约9~29ms) @ 0x691FCB ← Patch 2
       └── call ZtlSecureTear_long_ → 加密写入 mob+0x3A8
```

**Patch：**

| 地址 | 原指令 | 改为 | 说明 |
|------|--------|------|------|
| `0x691FB6` | `6A 15` (push 21) | `6A FF` (push -1) | 分支A: 21→-1 |
| `0x691FCB` | `83 C1 09` (add ecx,9) | `83 C9 FF` (or ecx,-1) | 分支B: 随机值→-1 |

完整4个死亡类型覆盖：

| 地址 | 函数 | 原指令 | 改为 | 引用死亡类型 |
|------|------|--------|------|-------------|
| `0x691FB6` | `sub_691F21` | `6A 15` | `6A FF` | 类型0-1 分支A |
| `0x691FCB` | `sub_691F21` | `83 C1 09` | `83 C9 FF` | 类型0-1 分支B |
| `0x692468` | `sub_692406` | `6A 0C` | `6A FF` | 类型2 |
| `0x692610` | `sub_6925AE` | `6A 27` | `6A FF` | 类型3 |

## 3. 怪物生成无敌状态

### 现象描述

怪物在地图中生成（入场）时，存在一个极短的过渡保护状态，此时怪物无法被攻击也无法攻击他人。

### 保护机制总览

```
服务端发送 OnMobEnterField 包
  ↓
CMobPool::OnMobEnterField (0x6A6C08) 处理入场
  ├── mob+0x390 = 从包中读取的初始状态
  ├── mob+0x400 = 入场时间戳（生成效果定时器）
  └── mob+0x318 = 无敌状态标志（关键字段）
       → CUserLocal::SetDamaged 中检查：非0则玩家不能攻击
       → sub_69F675 中检查：与某值XOR后为0则怪物不发起攻击
```

### 关键字段分析

#### mob+0x318 - 无敌/保护标志

**在玩家攻击怪物时 (`CUserLocal::SetDamaged`, 0x96435E)：**
```
0x9643FB: mov edi, [ebp+18h]       ; edi = 目标怪物指针
0x964400: cmp edi, ebx              ; 空指针检查
0x964402: jz skip_mob_checks        ; 无目标则跳过
0x964404: call CMob::IsMobOurTeam   ; 是友方怪物?
0x964409: test eax, eax
0x96440B: jz cannot_attack          ; 友方→不能攻击
0x964411: cmp [edi+318h], ebx       ; mob+0x318 == 0?
0x964417: jnz cannot_attack         ; 非0→不能攻击！（无敌保护）
```

**在怪物攻击其他目标时 (`sub_69F675`, 0x69F675)：**
```
0x69F698: mov eax, [ebx+318h]       ; 读取 mob+0x318
0x69F69E: xor eax, ecx              ; 与某参数值异或
0x69F6A0: jz skip_attack            ; 结果为0→跳过攻击
```

#### mob+0x400 - 生成效果定时器

在 `sub_690E09` 中被设置：
```
0x691411: mov [ebx+400h], eax       ; mob+0x400 = 当前时间 + 偏移量
```

在AI主函数 `sub_695DEE` 中被检查：
```
0x695FEA: mov eax, [ebx+400h]       ; 读取定时器
0x695FF0: cmp eax, edi               ; == 0?
0x695FF7: jz skip_processing         ; 为0→跳过处理
0x695FFD: mov ecx, [ebp-14h]         ; 当前时间
0x696000: sub ecx, eax               ; 当前时间 - 定时器
0x696004: jle skip_processing        ; 定时器未到期→跳过
0x696011: mov [ebx+400h], edi        ; 到期后清零
```

#### mob+0x41C - 攻击冷却定时器

在 `sub_69F675` 中有2000ms冷却检查：
```
0x69F6AB: lea ecx, [ebx+41Ch]       ; mob+0x41C 冷却定时器
0x69F6B1: mov edx, eax              ; 当前时间
0x69F6B3: sub edx, [ecx]            ; 距上次攻击时间差
0x69F6B5: cmp edx, 7D0h             ; 2000ms?
0x69F6BB: jl skip_attack            ; <2000ms→跳过攻击
```

### 入场包结构分析 (sub_690E09)

```
OnMobEnterField 包解析顺序:
  ├── Decode4 → 怪物ID (mob+0x174)
  ├── Decode2 → 初始X坐标 (mob+0x4CC/mob+0x4C4)
  ├── Decode2 → 初始Y坐标 (mob+0x4D0/mob+0x4C8)
  ├── Decode1 → CRC动作值 → ZtlSecureTear → mob+0x394/0x39C
  ├── Decode2 → Foothold X
  ├── Decode2 → CY/高度
  ├── Decode1 → 入场行为类型 (决定后续解析)
  │   └── -4(0xFC) → 特殊处理1
  │   └── -3(0xFD) → 特殊处理2
  │   └── -2(0xFE) → 特殊处理3  
  │   └── -1(0xFF) → 特殊处理4
  ├── Decode1 → 初始动作状态 → mob+0x390
  ├── Decode4 → 入场类型/召唤类型 → [ebp-30h]
  └── DecodeString → 怪物名称 (条件性)
```

### Hook方案

#### 方案A：移除无敌保护（推荐）

NOP掉 `mob+0x318` 的非零检查，允许玩家立即攻击刚生成的怪物：

```
地址: 0x964411 (CUserLocal::SetDamaged 内)
指令: cmp [edi+318h], ebx ; jnz loc_96582C

修改前: 39 9F 18 03 00 00 75 0E
修改后: 90 90 90 90 90 90 90 90  (NOP)
```

#### 方案B：同时移除怪物攻击自身的冷却限制

```
地址: 0x69F6B5 (sub_69F675 内)
指令: cmp edx, 7D0h ; jl loc_69F920

修改前: 81 FA D0 07 00 00 0F 8C XX XX XX XX
修改后: 90 x12
```

### 关键字段总览（补充）

| 地址/偏移 | 类型 | 含义 | 引用位置 |
|-----------|------|------|---------|
| `mob+0x318` | int | 无敌保护标志（非0=不能攻击/被攻击） | `0x964411`, `0x69F698` |
| `mob+0x400` | DWORD | 生成效果定时器（入场时设为未来时间） | `0x691411`, `0x695FEA` |
| `mob+0x41C` | DWORD | 攻击冷却定时器（2000ms限制） | `0x69F6AB` |

### Hook地址速查表

| 功能 | 地址 | 原始指令 | 修改为 | 长度 |
|------|------|---------|--------|------|
| 移除生成无敌保护 | 0x964411 | `39 9F 18 03 00 00 75 0E` | `90 x8` | 8字节 |
| 移除攻击冷却 | 0x69F6B5 | `81 FA D0 07 00 00 0F 8C XX XX XX XX` | `90 x12` | 12字节 |

## 4. 怪物特效系统

### 架构总览

怪物特效系统采用 **"入队-执行器"模式**，而非通常的函数同步调用：

```
触发源(服务端包/技能碰撞等)
  ↓
sub_690E09 (数据包处理器) — 解码服务端包解析出效果类型和参数
  ↓
mob+0x458 特效链表 ← 效果条目被推入链表 (带时间戳+类型+参数)
  ↓
CMob__OnMobAttacked (0x695DEE) — 每帧执行
  ↓
0x6969F9-0x696B47 特效队列遍历循环 ← 遍历链表检查时间戳
  ├─ 时间戳已到期 → sub_697A2D 创建COM视觉效果
  ├─ 声音标志设置 → sub_996B0C 播放音效
  └─ 处理完成 → sub_6A13B9 从链表移除
```

**关键发现**: 怪物特效**不是**在受击时直接创建的，而是先入队、再由独立的遍历循环统一调度执行。这是之前所有逐个NOP call站点都无效的根本原因。

### 特效队列数据结构

#### 链表头

| 偏移 | 说明 |
|------|------|
| `mob+0x458` | **特效链表头指针**（指向第一个特效条目） |
| `mob+0x44C` | 链表分配器（`sub_6A13B9` 用于分配/释放条目） |

#### 特效条目结构

```
特效条目 (每个约 0x1C 字节):
  +0x00   时间戳 (与当前时间比较判断是否到期)
  +0x04   效果类型ID
  +0x08   数据
  +0x0C   声音标志 (非0则调用 sub_996B0C 播放音效)
  +0x10   COM字符串指针 (效果名称/格式字符串)
  +0x14   附加参数
  +0x18   附加参数
```

### 遍历循环分析 (0x6969F9-0x696B47)

```
6969F9: mov  eax, [ebx+458h]     ; 读取特效链表头  ← 最理想的Hook点
6969FF: cmp  eax, edi             ; 判空(edi=0)
696A01: jz   0x696B47             ; 空则跳过整个循环
         ...
         ; [循环体前段]
696A5F: call sub_697A2D           ; 创建视觉特效#1
         ...
         ; [声音处理]
         ; ...
         ; [循环体后段]
696AF5: call sub_697A2D           ; 创建视觉特效#2
         ...
         ; [跳回暖]
         jmp  0x6969FF            ; 继续遍历下一个条目
696B47: ...                       ; 循环结束(正常出口)
```

双重调用 `sub_697A2D` 的原因：第一次处理"开始特效"（如闪光出现），第二次处理"持续特效"（如燃烧动画帧更新）。

### sub_697A2D (0x697A2D) 分析

```
sub_697A2D (怪物视觉特效创建函数)
  约定: __userpurge, 6个参数(24字节), retn 18h 清栈
  入口: mov eax, offset handler; call SEH_Probe (SEH注册)
  功能: 根据条目类型创建COM/DirectX视觉特效
  
  注意: 函数入口有SEH依赖, 直接改为retn会导致崩溃
```

### 最终Hook方案

#### ✅ 方案A: 替换读链表指令为 xor eax,eax （推荐）

在循环起点 0x6969F9, 将 `mov eax,[ebx+458h]`(6字节) 替换为 `xor eax,eax` + 4 NOP。

原理: eax 被清零后, 后续 `cmp eax,edi; jz exit` 判断链表为空直接跳过循环。
效果: 所有特效条目不被遍历, 视觉特效完全消失, 不影响声音和其他逻辑。

#### ✅ 方案B: jmp 跳过整个循环

在 0x6969F9 处改为 `jmp 696B47; nop` (6字节)。

原理: 无条件跳转到循环结束地址, 完全跳过遍历逻辑。
效果: 同方案A, 更彻底。

### 历史弯路记录

| 阶段 | 尝试方案 | 结果 |
|:----:|---------|:----:|
| 1-10 | 逐个NOP call站点（`sub_69960D`, `sub_694BF6`, `OnMobAttacked` 内call等） | ❌ 特效仍在 |
| **11** | **特效队列发现: mob+0x458 + 循环 0x6969F9** | **✅ 成功** |

**教训总结：**
- 怪物特效系统是"入队-执行器"模式, 非同步调用。逐个NOP call站点永远无法根除
- 越深入到COM/渲染层越错: 通用渲染入口影响人物特效
- 正确的方向是**在CMob__OnMobAttacked层面拦截特效调度**, 而非在渲染层面逐个block
- mob+0x458 特效链表是关键数据结构, 清空链表头就能阻止所有怪物受击特效

## 5. 怪物物理/动画更新

### sub_9BCA34 (0x9BCA34)

怪物每帧物理+动画更新的核心入口：

```asm
9bca34: push esi
9bca35: mov esi, ecx           ; this = 物理子对象
9bca37: mov eax, [esi]
9bca39: call dword ptr [eax+30h]  ; vtable[12]: 检查是否需要更新
9bca3c: test eax, eax
9bca3e: jz exit                  ; 74=JE → EB=JMP=总是跳过(怪物冻结)
9bca40: ...
9bca4e: call dword ptr [eax+34h]  ; vtable[13]: 物理+动画更新(参数0x1E=30帧)
```

**冻结补丁：** `0x9BCA3E` 的 `74` → `EB` (JE→JMP)，怪物完全不动。

> ⚠ 冻结后怪物所有行为(行走/待机/受击/死亡)全部停止，范围太广不适合单独用来屏蔽 hit 特效。

### 碰撞盒解密函数

`sub_4149A7` (0x4149A7) — 从加密存储解密碰撞数据写到 mob+0x3D4：
- 从 `[src+0x00]~[src+0x20]` (3组加密值) 解密
- 写入 `[dst+0x00]~[dst+0x08]` (3个int: left/top/right)
- 调用者包括：MsgDisplay_Suppress、sub_6940BC、sub_698BD6、sub_69C432(动画状态)、CUser__CreateSkillEffect 等

> ⚠ 碰撞盒每帧更新(即使怪物待机)，不适合做断点来追踪攻击特效

## 6. 崩溃风险评估

| 风险场景 | 概率 | 后果 | 说明 |
|---------|------|------|------|
| 跳过死亡动画后怪物残留 | 极低 | 显示残留 | 延迟队列清理后恢复正常 |
| 跳过死亡动画导致指针悬空 | 极低 | 崩溃 | 若某系统还在引用怪物对象 |
| 移除无敌后秒杀刚刷新的怪物 | 低 | 无崩溃 | 服务器可能会校验 |
| 移除攻击冷却导致怪物攻速过快 | 低 | 表现异常 | 攻击动画可能被频繁打断 |
| 入场动画跳过 | 低 | 显示异常 | 部分Boss召唤特效被跳过 |
