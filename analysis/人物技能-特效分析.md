## 技能调用链

### 本地玩家技能使用

```
玩家按键/点击技能
       │
       ▼
OnKeyAction (0x9535F1)
  │  按键1-3: NPC对话/坐下/捡取
  │  按键4-9: → OnSlotAction (0x955C96)
  │
  └──→ CUserLocal__DoActiveSkill (0x968550)
          │
          ├─ 判断技能类型 (通过技能ID)
          │   ├─ 3121004, 3221001, 1121001-1321001, 2121001-2321001: 特定技能处理
          │   └─ 其他 → sub_97AE26 (通用处理)
          │
          ├─ CAvatar::GetOneTimeAction → 检查当前动作状态
          ├─ CAnimationDisplayer::RemovePrepareAnimation / ShowSkillPrepare
          └─ 分发到具体攻击函数
              ├─ CUserPreview::DoMeleeAttack → 近战
              ├─ CUserPreview::DoShootAttack → 远程
              └─ MsgDisplay_Suppress / sub_95FE76 / sub_95C5B2 → 特殊技能
```

```
CUserPreview::DoMeleeAttack (0x9864B6)
  │
  ├─ CAvatar::GetOneTimeAction → 检查动作状态
  ├─ get_random_melee_attack_action → 随机攻击动作

  ├─ sub_93D342 → 准备特效
```

## 特效系统架构

### CAnimationDisplayer 系列

```
CAnimationDisplayer
  ├─ Effect_General        (0x43286E) — 通用特效初始化
  ├─ Effect_Init           (0x43283B) — 特效对象置零
  ├─ Effect_ByItem         (0x4387E3) — 道具触发的特效
  ├─ Effect_Catch          (0x438B63) — 捕捉特效
  ├─ Effect_SkillBookUsed  (0x43C511) — 技能书使用特效
  ├─ Effect_RewardRullet   (0x43C9EB) — 转盘奖励特效
  └─ Effect_Tremble        (0x43D36D) — 震动特效
```

### CAnimationDisplayer__Effect_PlayCom (0x43E1D7)

**COM 特效播放核心**，是所有特效的最终执行者。

- 使用 COM 接口(`_GUID_7600dc6c...`) 创建和管理特效对象
- 处理特效字符串路径、坐标、层级参数
- 被 100+ 位置调用，涵盖 UI、技能、怪物、物品等所有特效类型
- 不适合直接屏蔽（影响面太广）

### CUser__CreateSkillEffect (0x93A008)

**技能视觉特效核心渲染函数**（10470 字节），是游戏中最大的函数之一。

- 参考字符串 "l", "/1", "/0"（特效动画路径的组成部分）
- 调用 `CAnimationDisplayer__Effect_PlayCom` 播放 COM 特效
- 调用 `CAnimationDisplayer::Effect_General` 创建通用特效
- 从 `Skill/*.img` 加载技能动画数据
- 调用者包括：`OnAttack`, `DoMeleeAttack`, `DoShootAttack`, `OnEffect` 等

## 方案1 可行性分析：屏蔽技能准备特效

### 目标

让 `CAnimationDisplayer__Effect_SkillPrepare` (0x43D3E7) 不被调用，从而禁用技能准备特效。

### 调用点

该函数 **仅有一个调用点**：

```
CUser::ShowSkillPrepare (0x93CA0A) + 0xCB (偏移)
  └─ 0x93CB05: call CAnimationDisplayer__Effect_SkillPrepare
```

### 函数原型

```c
int __userpurge CAnimationDisplayer__Effect_SkillPrepare@<eax>(
    int a1@<ebx>, _DWORD *a2@<ebp>, int a3@<edi>, int a4@<esi>,
    int a5, int a6, int a7, int a8, int a9, int a10, int a11, int a12)
```

### 调用上下文 (ShowSkillPrepare)

```c
if ( v11 )  // 有有效的动画帧
{
    // ... 设置时间参数 ...
    CAnimationDisplayer__Effect_SkillPrepare(v15, v16, v17, v18, v19, v20, v21, v22);
    // ← NOP 掉这里
}
v14 = a1[2];
if ( v14 )
    sub_4030AF(v14);  // 释放资源 (NOP后仍会执行)
return;  // 返回 (不依赖返回值)
```

### 安全性评估

| 项目 | 分析 |
|------|------|
| 返回值依赖 | ❌ 不依赖 (`ShowSkillPrepare` 是 void) |
| 后续清理 | ✅ 依然执行 (sub_4030AF 在 call 之后) |
| 调用者数量 | ✅ 仅 1 个调用者 |
| 游戏逻辑影响 | ✅ 仅视觉效果，不影响技能判定 |
| 结论 | **安全，可实施** |


### 局限性

方案1 仅屏蔽 **技能准备特效**（`ShowSkillPrepare` 触发的部分），不屏蔽：

| 特效类型 | 处理函数 | 是否屏蔽 |
|---------|---------|:-------:|
| 技能准备光效 | `CAnimationDisplayer__Effect_SkillPrepare` | ✅ |
| 攻击残影 | `CUser::RegisterAfterimage` | ❌ |
| 远程技能特效 | `CUser__CreateSkillEffect` | ❌ |
| 怪物受击特效 | `CMob::ShowHitEffect` | ❌ |
| 地面领域特效 | `CField__CreateAffectedAreaEffect` | ❌ |
| UI 特效 | `CAnimationDisplayer__Effect_PlayCom` 调用 | ❌ |

## 方案3：禁用所有技能视觉特效

### 原理

在 `CUser__CreateSkillEffect` (0x93A008) 入口处，将条件跳转改为无条件跳转到函数退出，跳过所有特效创建代码。

函数入口流程：
```asm
93a008: mov eax, offset handler     ; SEH注册
93a00d: call SEH_Probe              ; SEH设置+栈探测
93a012: sub esp, 2ECh                ; 分配栈空间
93a018: push ebx                     ; 保存寄存器
93a019: push esi
93a01a: push edi
93a01b: mov ebx, ecx                ; this
93a01d: xor edi, edi
93a01f: cmp [ebx+3B8h], edi         ; 标志检查
93a025: mov [ebp-28h], this
93a028: jnz exit                    ; ← 改为无条件 jmp exit
                                    ;    (原: 标志!=0才跳)
```

修改后：SEH 正常设置 → 栈帧正常分配 → 寄存器正常保存 → **直接跳到函数退出** → 干净返回。


### 安全性评估

| 项目 | 分析 |
|------|------|
| SEH 保护 | ✅ 函数入口正常设置后才跳转 |
| 栈帧清理 | ✅ leave/ret 正常执行 |
| 寄存器恢复 | ✅ ebx/esi/edi 在退出代码中恢复 |
| 调用点 | ✅ 覆盖所有 20 个调用者 |
| 返回路径 | ✅ 使用函数原有退出代码 (0x93C8D7) |

## 未解决的技能 Hit 特效（技能WZ的hit节点）

### 问题

技能 1001005 命中怪物时，怪物身上会出现粉色击打特效。该特效来自技能 WZ 文件的 `skill/1001005.img/hit/0` 节点，是独立的动画特效。

### 已尝试的 patch（全部无效）

| # | 目标 | 方法 | 结果 |
|:-:|------|:----:|:----:|
| 1 | `CUser__CreateSkillEffect` (0x93A008) | jmp exit | ❌ |
| 2 | `sub_93CB27` (0x93CB27) | jmp exit | ❌ |
| 3 | `CUserRemote__CreateAttackImpact` (0x98EAE3) | jmp exit | ❌ |
| 4 | `CUserRemote__CreateAttackHitFeedback` (0x98FDDF) | jmp exit | ❌ |
| 5 | `CUserRemote__CreateAttackHitFeedback2` (0x98E572) | jmp exit | ❌ |
| 6 | `sub_990906` (0x990906) | jmp exit | ❌ |
| 7 | `CMob::ShowHitEffect` (0x69E55C) | jmp exit | ❌ |
| 8 | `CMob::OnSpecialEffectBySkill` (0x69C359) | jmp exit | ❌ |
| 9 | `Effect_General` in OnMobAttacked (0x696440) | NOP | ❌ |
| 10 | `Effect_General` in sub_694BF6 (0x69532F) | NOP | ❌ |
| 11 | `MsgDisplay_Suppress` (0x9573A6, 消息显示抑制函数) | retn | ❌ 导致技能无法释放 |

### 已知信息

- 字符串 `"1001005/hit/0"` 在内存 `0x1A56A6CC`（WZ 数据加载后的路径）
- 该字符串在代码段没有直接引用，通过 WZ 节点系统间接访问
- 所有已知的特效创建函数（CreateSkillEffect、Effect_General、Effect_PlayCom、sub_93CB27）都不是目标

### 推测

1. Hit 特效可能通过**COM 对象直接创建**，不经过 CAnimationDisplayer 系统
2. 可能在 `CSkillInfo`（0x76xxxx）的函数中读取 WZ hit 节点并直接创建 COM 动画
3. 通用渲染引擎在攻击碰撞检测时触发，走独立路径

### CSkillInfo 分析

| 函数 | 地址 | 大小 | 说明 |
|------|:----:|:----:|------|
| `CSkillInfo::GetSkill` | 0x769B51 | 0x4B | 获取技能数据 |
| `sub_76E2FA` | 0x76E2FA | 0x268 | 技能数据管理(每项484字节)，调用 sub_76C83B 加载 |
| `sub_76C83B` | 0x76C83B | 0x1454 | **技能属性加载核心** — 使用 `%07d` 格式化技能ID，从 StringPool 加载30+个属性 |
| `sub_7741A2` | 0x7741A2 | — | 技能数据内存分配 |
| `CSkillInfo::GetSkillLevel` | 0x76EACD | — | 获取技能等级 |

`sub_76C83B` 加载的属性（通过 StringPool ID）：
- 2017, 2170: 基础属性
- 1766-1777, 1458-1478: 各种技能属性
- 817-819, 3330-3331, 3414, 5486, 5489: 特殊属性
- 1341, 1451, 1473-1478: 更多效果属性
- 896, 2645: 效果路径相关

### 关键结论

Hit 特效的创建代码**不在怪物端**（所有怪物端特效函数已分析并patch），而是在**玩家端技能系统**中。
推测存在一个未找到的通用函数，专门负责从已加载的技能数据中读取 "hit" 节点并创建动画。

### 后续建议

需要在 CE 中使用交互式调试：
- 用 **VEH 调试器** 对内存中的 `"1001005/hit/0"` 字符串区域下断点
- 或者使用 CE 的 **Ultimap2 / Code Finder** 追踪攻击时执行的代码
- 重点搜索范围：`0x769000`-`0x76F000` (CSkillInfo 函数)
- 或者在 CE 中搜 `hit` 相关字符串的引用

## 怪物后仰僵直动画分析

### 问题描述

当前 8 个 patch 已能屏蔽：
- 人物技能视觉特效 ✅
- 武器刀光残影 ✅
- 怪物受击闪烁 ✅
- 怪物技能附加特效（冰冻/中毒等） ✅
- 打击粒子/命中反馈 ✅

但怪物**被击中后的后仰僵直动画**仍然存在 ❌。

### 分析过程

#### 尝试1: INT3 断点追踪

在 `CMob::OnAffected` / `CMob::OnDamaged` / `CMob::OnSpecialEffectBySkill` 下 INT3 → 无命中（这些是服务器包处理函数，本地攻击不走这里）

#### 尝试2: INT3 追踪 CMob__OnMobAttacked

在 `CMob__OnMobAttacked` (vtable[0], 0x695DEE) 下 INT3 → 数据量太大卡死（40只怪物同时攻击产生海量断点）

#### 尝试3: 条件 AA 钩子

写 AA 脚本在 OnMobAttacked 入口检测指定怪物地址 → 怪物死后地址失效，不实用

#### 尝试4: 静态分析 CMob__OnMobAttacked

OnMobAttacked 内部调用链：
```
CMob__OnMobAttacked (0x695DEE)
  ├─ ZtlSecureFuse 解密各种状态
  ├─ CMob::ShowDamage (多次) — 伤害数字
  ├─ sub_699C57 — 怪物移动/动画状态更新
  │   └─ sub_9C3E91 — 物理引擎更新
  │       ├─ 加密的 double 坐标/速度计算
  │       ├─ vtable[5] (*(*v20+20)) — 设置位置
  │       └─ vtable[6] (*(*v20+24)) — 步进动画帧 → ★ 后仰动画触发点
  ├─ CMob__OnDamaged — 受伤判定
  ├─ sub_694BF6 — 特效处理
  │   ├─ CAnimationDisplayer::Effect_General
  │   ├─ CAnimationDisplayer::Effect_Tremble
  │   └─ CUserLocal::SetDamaged
  └─ CField::ShowMobHPTag — 显示HP标签
```

#### 尝试5: NOP CMob__OnMobAttacked 入口

在 0x695DEE 放 retn 测试 → **怪物完全不动，死后不消失** — 说明整个受击反应都在这一个函数内处理，无法简单跳过。

### 结论

| 方法 | 结果 | 原因 |
|------|:----:|------|
| INT3 断点 | ❌ | 数据量太大，游戏卡死 |
| 数据断点 (find_what_writes) | ❌ | MCP bridge 不稳定 |
| 条件 AA 钩子 | ⚠️ | 怪物地址动态变化 |
| 静态分析 patch | ❌ | 后仰在物理更新虚函数中，与核心逻辑耦合 |
| NOP 整个 OnMobAttacked | ❌ | 怪物完全失去反应，死亡也不消失，无法独立禁后仰 |

**后仰僵直动画** 由 `sub_9C3E91` 内部的 vtable 虚函数调用 `(*(*v20+24))(v20, v111)` 触发，该调用既是动画更新也是物理更新，无法与正常逻辑分离。

### 后续建议

需要 **CE VEH 调试器** 手动操作：
1. 通过 CMobPool 枚举当前地图怪物
2. 用 VEH 调试器下硬件断点（数据断点）监控怪物状态变化
3. 攻击后读取断点日志，找到动画状态写入点
4. 再分析是否可以单独 patch

## CMobPool 结构速查

### 全局指针

| 地址 | 说明 |
|------|------|
| `0x00BDD49C` | **CMobPool 指针** |
| `0x00BDD490` | 人物基址 |

### CMobPool 结构

```
CMobPool (this → [0xBDD49C])
  ├─ +0x00: vtable (0x00B04FE0)
  ├─ +0x04: 列表哨兵
  ├─ +0x0C: 怪物数量 (int)
  ├─ +0x28: 第一个怪物槽指针 (ZArray结构)
  ├─ +0x5C: 更新计时器(+0x5C~+0x60)
  └─ +0x80: 相关数据
```

### 枚举怪物 (ZArray 遍历)

```
CMobPool::FindHitMobInManyRects 揭示的遍历算法:

slot = [pool + 0x28]   // 第一个槽
while slot != 0:
    mobPtr = [slot + 4]    // CMob* 指针
    if mobPtr != 0:
        // mobPtr[0] = vtable (0x00B03A14 或 0x00B04F20)
        // mobPtr[0x2C] = X坐标(加密)
        // mobPtr[0x30] = Y坐标(加密)
    
    v12 = [slot - 12]     // 下一个槽偏移
    slot = (v12 != 0) ? v12 + 16 : 0
```

### CMob 对象结构（部分）

| 偏移 | 说明 |
|------|------|
| +0x00 | vtable (0x00B03A14 = CDrop/CLife 基类) |
| +0x04 | vtable (0xB039F0 = 接口类) |
| +0x08 | vtable (0xAFE3F0 = 物理对象) |
| +0x0C | 标志位 |
| +0x2C-0x30 | 坐标 (加密存储) |
| +0x124 | 怪物ID (ZtlSecureTear 加密) |
| +0x12C | 怪物ID 校验 |
| +0x124+ | 加密数据块 |
| +0x2C8 | 移动状态(加密) |
| +0x36C | 计时器相关 |
| +0x376 | CMobTemplate 指针 |
| +0x378+ | CMobTemplate 数据 |
